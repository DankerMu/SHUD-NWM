## Context

Issues #1766, #1712, #1765 (priority:high), #1647 — node-27 operations signal hardening. All four touch production units/wrappers or the shared autopipeline connection helper, so fixture level = `expanded`, repair intensity = `high`. Live facts used here (probed 2026-09-02, read-only): root volume 98 GB / 14 GB free, `/tmp/pytest-of-nwm` 3.2 GB, `TMPDIR` unset in the login shell; the retention and governance units carry `StandardOutput/StandardError=append:`; the governance unit has no `OnFailure=`. Repo facts (fixture review, revision 1): `_connect` (`scripts/node27_autopipeline.py:887`) is the only `psycopg2.connect` site and has 12 call sites, including the forcing-handoff ingest (`:1781`, bulk `execute_values` + `_lock_interp_weight_scope`) and the geometry backfill (`:1320`); `_STATS_GUARD_IDENT_RE` is `^[A-Za-z0-9_]+$` (`:1440`); `DATABASE_URL_ALLOWED_QUERY_KEYS` (`:189-196`) admits `connect_timeout`; the only `systemd.err` mentions outside unit files are the units' own `StandardError=` lines and one historical product-archive receipt README — no runbook or checklist `tail … systemd.err` command exists.

## Goals / Non-Goals

**Goals**: the §8.6 escalation criterion counts real drop-phase refusals; the retention alert body carries `refusal_reason`; the governance critical signal is audible; no autopipeline connect (10 s) and no single non-guard statement (600 s; guard legs keep 120 s) can hang indefinitely, so every tick terminates (a tick may still legitimately outlast the 10-min timer and be skipped by `flock -n`, as today); two small fail-closed/parse hardenings.

**Non-Goals**: `lock_timeout` values or timer schedules (#1664/#1708); converting H5 fail-closed to skip-and-continue; the 8 sibling `append:` units (byte-identical, registered only); `/dev/md0` observability; docker-image cleanup on node-27 (operator, root); governance receipt schema shape; any other script's connection timeouts; whole-repo env-flag normalisation; counting `RETENTION_CONCURRENT_INVOCATION` / `RETENTION_UNCAUGHT_ERROR` as no-progress (the first means a previous tick is still working, the second is a bug that the alert already surfaces).

## Decisions

### D1 (#1766) — count drop-phase refusals, not lock classifications
The criterion's intent is *progress*, and any drop failure is zero progress. The runbook command becomes a count of `RETENTION_DROP_FAILED:` occurrences on the per-tick stderr diagnostic line (the runner emits exactly one such line per refused tick; the drop-timing line carries no wire code), bracketed the same way as item 5. Alternative (a new `drop-wall(57014)` marker) rejected: a new wire token that must stay byte-identical across code/runbook/schema for no extra information. The anchor test drives the runner with fake cursors raising 57014, 55P03 and 40P01 and asserts each refused tick emits the counted anchor exactly once and a clean tick emits it zero times; the runbook command text is asserted byte-for-byte against the test's pattern (existing `LOCK_CONTENTION_MARKER_PREFIX` discipline).

### D2 (#1712) — tee to the log, stderr to the journal, RC from PIPESTATUS
Wrapper line 147 becomes `"$PYTHON_BIN" "$SCRIPT" "$@" 2>&1 | tee -a "$LOG_FILE" >&2; RC=${PIPESTATUS[0]}`. `retention.log` stays a complete transcript (item 5 brackets and the D1 anchor are unaffected), and the same bytes reach the wrapper's stderr, which the unit now routes with `StandardError=journal`; `StandardOutput=append:systemd.log` is kept unchanged (it receives nothing from the wrapper — the `start` / `done rc=` bracket lines are appended straight to `retention.log`, and the runner lane now goes to stderr — so `systemd.log` is a stdout catch-all, not the bracket destination). The dumb handler is untouched: `journalctl -n 30` now naturally contains the runner's `_emit_stderr_diagnostic` JSON line with the redacted `refusal_reason`. The `systemd.err` lane retirement is scoped to `infra/systemd/nhms-node27-timeseries-retention.service` only; the runbook gains the `journalctl --user -u nhms-node27-timeseries-retention.service -n 30 --no-pager` command as the operator's first stop, and §8.6 item 8's KNOWN LIMITATION is rewritten. Redaction is unchanged (`_redact_error_text` upstream of the diagnostic). Alternative (lane-specific tail in the handler) rejected: violates #1664 D6 "no per-lane logic".

### D3 (#1765) — bound growth in repo config, make the signal audible, move the lock
- `pyproject.toml` `[tool.pytest.ini_options]` gains `tmp_path_retention_policy = "failed"` (pytest ≥7.3; repo pins 9.x). Passing tests' `tmp_path` dirs are removed at session end everywhere (local, CI, node-27). No `--basetemp` in shared config: it clears its target every run and would hit Mac and CI.
- node-27 host discipline: `mkdir -p /home/nwm/tmp && export TMPDIR=/home/nwm/tmp` in the nwm login profile so pytest's `pytest-of-nwm` root lands on `/home`. `TMPDIR` fails open (`tempfile.gettempdir()` silently falls back to `/tmp` when the directory is missing), hence the `mkdir -p`, and the receipt asserts where `pytest-of-nwm` actually landed, not only `df -h /`. Must-preserve: `/home` is the pgdata + object-store volume; the growth bound comes from the retention policy (passing tests leave nothing), not from volume size — the runner's own ENOSPC reasoning (`scripts/node27_timeseries_retention.py:1069-1072`) concerns that volume and stays valid. Recorded in the tier runbook and bringup checklist; applied post-merge in the receipt session.
- `scripts/node27_resource_governance.py::main` returns 1 when any recommendation has `severity == "critical"`, after writing the receipt unchanged (`status` stays `completed`; schema untouched) and printing one `RESOURCE_GOVERNANCE_CRITICAL:<code>` line per critical recommendation to stderr. `--quiet` suppresses stdout only.
- `infra/systemd/nhms-node27-resource-governance.service` gains `OnFailure=nhms-node27-unit-failure-alert@%n.service` and `StandardError=journal`; the wrapper adopts the D2 tee geometry and defaults `LOCK_PATH` to `$LOG_ROOT/node27-resource-governance.lock` (already `/home/nwm/node27-resource-governance-logs`). The two sibling `/tmp` locks (`node27_raw_retention_once.sh`, `node27_timeseries_retention_once.sh`) are recorded as known/accepted in the runbook, not changed here.
- Capacity-check discipline: `df -h / /home /data/GHDC` in `instructions/agents/shared.md:23` (regenerate `CLAUDE.md`/`AGENTS.md` with the repo generator, never hand-edit), `current-production-ops.md` capacity section (line ~2076) and the bringup checklist.

### D4 (#1647) — one helper, bounded everywhere; fail-closed identifier; falsy set
- `_connect(database_url, **kwargs)` applies `connect_timeout=_CONNECT_TIMEOUT_SECONDS` (10) and `options="-c statement_timeout=<ms>"` with module default `_QUERY_TIMEOUT_MS = 600_000` unless the caller supplies them; the stats guard passes its own `STATS_GUARD_TIMEOUT_MS` and keeps its existing per-relation `SET statement_timeout`. The default is one tick interval (10 min), not the compression lane's 60 s catalog budget: ingest statements legitimately run for minutes under lock contention (retention's 300 s wall is hit while blocked by ingest, #1766), and the goal is "terminates", not "fast". Accepted consequence (explicit): a single non-guard statement longer than 600 s is cancelled; on the ingest path `_process_forcing_stage` marks the run `outcome: failed` (`:1809-1821`) which feeds the tick's rc (`:2569-2571`), and the next tick retries. The two stats-guard connections are excluded from this claim: a cancelled per-relation `ANALYZE` is caught by the per-relation isolation handler and recorded on that relation's entry (`entry["status"] = "failed"`, `:1491-1495`) while the guard summary stays `completed`; only a cancelled connect or candidate query reaches the summary-level `status="failed"` (`:1583`, `:1627`); in both cases the tick rc deliberately ignores the guard (#1643 semantics, untouched). Recorded as a regression row and observed on node-27 (T9c reads the longest statement of the dry tick from the receipt/`pg_stat_activity`). Implementation hint: DSN precedence for `connect_timeout` reuses the preflight's existing DSN query parse (`:284`), not a second URL-parsing idiom; `options` has no DSN path (not an allowed query key), so only the Python caller can override the statement budget. libpq `options` is chosen over a post-connect `SET` because a `SET` issued inside psycopg2's implicit first transaction is undone by a rollback. Operator DSN precedence (must-preserve): when the DSN query string carries `connect_timeout` (allowed key), `_connect` does not pass the kwarg, so the DSN value wins — mirror of #1714 T4 for `application_name`; pinned by a test with `?connect_timeout=3`. Test pins: default kwargs, stats-guard value, explicit Python-caller override, DSN precedence, and the `make_dsn` merge with a DSN that already carries `application_name` unchanged.
- `scripts/node27_timeseries_compression.py::qualified_chunk` validates both parts against the same pattern as `_STATS_GUARD_IDENT_RE` (`^[A-Za-z0-9_]+$`, mirrored as a module constant with a comment naming the autopipeline anchor) and raises `ValueError` otherwise; the module has no consumer of the property today — every chunk reference is a bound `%s::regclass` parameter (the ride-along ANALYZE that #1647 anchored on was removed in f5069257 before this change) — so the helper is defence in depth for any future interpolation site. Test: the property raises directly on `"`, `;`, whitespace and empty parts; a byte-identity test pins the two patterns equal; a module-scan test asserts no f-string SQL names a chunk.
- `NODE27_AUTOPIPE_STATS_GUARD`: `value.strip().lower() in {"0","false","no","off"}` disables; parametrized test over the four values plus `"1"`/`"ON"`; runbook lists the accepted values.

## Invariant Matrix

- Governing invariant: every drop-phase refusal, critical governance finding and autopipe backend on node-27 is (a) counted by the runbook criterion that claims to count it, (b) delivered to the journal the alert handler quotes, and (c) bounded so that no connect or single statement can hang indefinitely (every tick terminates) and no test run can fill the host that must deliver it.
- Source-of-truth identity/contract: `RETENTION_DROP_FAILED:` diagnostic line (runner stderr); wrapper `RC`; unit `StandardError=journal` + `OnFailure=`; governance recommendation `severity`; `_connect` kwargs and DSN precedence.
- Producers: `node27_timeseries_retention.py::_emit_stderr_diagnostic`; `node27_resource_governance.py::main`; `node27_autopipeline.py::_connect`.
- Validators/preflight: anchor tests in `tests/test_node27_timeseries_retention.py`; `qualified_chunk` regex + identity pin; stats-guard flag parser.
- Storage/cache/query: `retention.log`, `resource-governance.log`, journal; governance receipt JSON (shape unchanged).
- Public routes/entrypoints: the two `_once.sh` wrappers and their units; `node27_autopipeline.py` tick (11 `_connect` call sites, AST count).
- Frontend/downstream consumers: `nhms-node27-unit-failure-alert@.service` handler (unchanged); operators reading §8.6.
- Failure paths/rollback/stale state: `tee` failure must not alter `RC`; governance receipt is written before the non-zero exit; stats guard failure still leaves tick rc unchanged (#1643); a >600 s statement cancels instead of wedging — per-run: run `failed` + rc≠0; display-ready seed: `seed_failed` + summary + rc≠0; pre-loop/publish: propagates, no summary, rc≠0; decline count: `declines_active: null`, rc unchanged (by design).
- Evidence/audit/readiness: node-27 receipts — refused-tick journal + mail body; governance forced-critical exit + mail; autopipe dry tick receipt with stats-guard section unchanged and longest statement noted; `pytest-of-nwm` location + `df -h /` before/after.
- Regression rows:
  - retention runner refuses with 57014 -> exactly one `RETENTION_DROP_FAILED:` diagnostic line; runbook count = 1; wrapper `RC` = runner rc; `retention.log` has `start`/`done rc=` bracket + the line.
  - runner exits 0 -> zero counted lines; `RC=0`.
  - governance audit with a critical recommendation -> receipt written, `status: completed`, stderr `RESOURCE_GOVERNANCE_CRITICAL:<code>`, exit 1; no critical -> exit 0.
  - `_connect(url)` -> `psycopg2.connect(url, connect_timeout=10, options='-c statement_timeout=600000', fallback_application_name='nhms-autopipe')`; stats guard -> its own budget; `url?connect_timeout=3` -> no `connect_timeout` kwarg (DSN wins); a fake backend that sleeps past the budget on a non-guard connection -> `QueryCanceled`; per-run → run outcome `failed`, tick rc≠0; display-ready seed → `seed_failed`, summary emitted, rc≠0; pre-loop/publish → propagates, no summary, rc≠0; `_active_decline_count` → `None`, rc unchanged; next tick unaffected in every shape; the same on a guard `ANALYZE` -> that relation's entry `status="failed"`, summary `completed`; on the guard connect/candidate query -> summary `status="failed"`; tick rc unchanged in both (#1643 row preserved).
  - `qualified_chunk` with `_hyper_1_2_chunk"; DROP` -> `ValueError`, no cursor call; compression pattern == `_STATS_GUARD_IDENT_RE.pattern`.
  - Unchanged sibling: the 7 other `append:` units byte-identical; `nhms-node27-unit-failure-alert@.service` changed comment-only (consumer inventory + standing-critical note, round-1 fix); product-archive receipt README untouched.
