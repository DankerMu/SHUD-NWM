### D5 (#2183) — direction B: a registered-additions ledger, frozen baseline untouched

- Chosen over A because A turns equality into lower bounds and weakens the #1913 "migration was a pure move" proof the issue forbids weakening; B keeps every equality form.
- New tracked ledger `tests/fixtures/basins_registry_partition_additions.json` (`schema: basins-registry-partition-additions/v1`, `additions: []`). Because it is a hand-edited guard input, it gets a path-exact selector rule targeting `tests/test_select_ci_tests.py` (neither flag); otherwise a ledger-only PR selects nothing and fails only on master. A separate file, not a new oracle key, so `basins_registry_partition_oracle.json` stays byte-identical and its self-digest, `REGISTRY_PARTITION_FROZEN_DIGESTS`, contract/source anchors and the #1903 transition record are not touched.
- Record shape (one per added test function): `issue` (int), `base_commit` (40-hex), `owner` (one of the six partitions **other than** the retained core `tests/test_basins_registry_import.py` — never the helper), `name`, `row` (the same 7-field tuple the definitions guard computes), `nodes` (collected node suffixes), `integration_nodes` (subset of `nodes` that carry the integration marker).
  - Retained core excluded as owner: its bug008 literal command (`"2 passed, 16 deselected"`, asserted in both the execution guard and `test_registry_partition_bug008_command_still_passes_exactly_two_cases`) runs on that file alone; excluding it keeps those literals untouched instead of adding a keyword-collision rule. Known limit.
  - Outcome rule: a registrable non-integration node must pass unconditionally under the sandboxed child pytest, and an integration node must skip there. Additions that skip/xfail otherwise are not registrable (known limit; the count mismatch fails loudly).
- Guards re-based on `frozen ∪ additions` (a pure union; with an empty ledger every guard computes exactly today's expected values and literals). Per site:
  - collection (`..._collects_its_frozen_suffixes_exactly_once`): observed == frozen `node_suffixes` ∪ all `nodes`; the `96` count literal becomes `96 + Σ|nodes|`; the `digests.suffix` check is computed over observed minus addition nodes;
  - integration (`..._integration_suffixes_and_owner_counts_are_frozen`): observed == frozen `integration_suffixes` ∪ all `integration_nodes`; `digests.integration_suffix` over observed minus additions; `owner_of` built from frozen rows **plus** ledger owners (no `KeyError` on an addition); per-owner counts = frozen + additions;
  - definitions: each partition `test_*` FunctionDef must match its frozen row or its addition row exactly; the observed name set must equal frozen ∪ addition names; the `== 94` and `owner_map` digest assertions stay, computed over the frozen subset;
  - execution: expected strings = frozen literals + deltas (default: `passed += |nodes − integration_nodes|`, `skipped += |integration_nodes|`; `-m "not integration"`: `passed += |nodes − integration_nodes|`, `deselected += |integration_nodes|`; `-m integration`: `skipped += |integration_nodes|`, `deselected += |nodes − integration_nodes|`). The frozen literals remain literals; bug008 untouched;
  - ledger integrity (pure checker, named assertion per rule): schema string; required keys; `nodes` non-empty and every node satisfies `node.split("[", 1)[0] == name`; nodes disjoint from frozen `node_suffixes` and from other records; `integration_nodes ⊆ nodes`; names unique and ∉ frozen `rows`; `row` is a list of 7 strings (`ledger.row_shape`) and `row[0] == owner` (`ledger.row_owner_mismatch`, so the owner the allow-list/provenance/counts use is the file the definitions guard checks); non-empty `integration_nodes` requires owner ∈ `REGISTRY_PARTITION_DATABASE_AUTHORITY` (`ledger.integration_owner_not_database_authority`, so the node reaches the real-DB lane); owner ∈ the six allowed partitions; then git checks in order, each with a named message (no bare `CalledProcessError`): `base_commit` resolves (`rev-parse <sha>^{commit}`), is an ancestor of `HEAD` (`merge-base --is-ancestor`), the owner blob exists at `base_commit`, and `name` is absent from that blob.
  - What actually prevents laundering is "name ∉ frozen rows" plus exact row identity for every definition; the `base_commit` absence check is a weak provenance check (the author chooses the commit) and is documented as such.
- Proof mechanics: definitions and ledger-integrity checks are refactored into pure functions over `(oracle, ledger, partition text reader, blob reader)` (precedent: `_registry_members_from_text`) and proved on in-memory/tmp text; collection/integration/execution expected-value math is unit-tested by injecting observed suffix lists and count strings. Only the live tree with the real (empty) ledger runs child pytest. No tmp git repository is required; git-check failure paths are proved with an injected blob reader / unknown SHA against the real repo.

- Every proof that reads the real tree unions its in-memory records with the REAL ledger's additions, so the first genuine addition does not red them; one proof re-runs them under a simulated non-empty ledger.
- The unregistered-definition failure message prints the observed row and node suffixes, which is the procedure's data source for a new record: the author copies it into a reviewed ledger entry. Frozen rows are never recomputed.
- Procedure written in the #1913 rationale comment block, which also stops describing `.workplans/issue-1913/` as a live generator (gitignored and gone; the optional contract check stays as a no-op-when-absent arm, stated as such).

## Risks / Trade-offs

- A ledger entry lets an added test evolve only by updating its pinned row — the same ceremony the #1903 transition carries; accepted.
- Execution-delta derivation assumes a non-integration node passes and an integration node skips under the sandboxed child pytest; any other outcome fails loudly (count mismatch), not silently.
- Sequencing: issues #2260/#2191/#2198/#2230 are implementation pass 1; #2183 is pass 2 on the same branch. If #2183 fails to converge within the review budget it is descoped from this PR (terminal `descoped` line for #2183 only).
