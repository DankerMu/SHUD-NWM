## Decisions

### D1 (#1779) — authority state, not a fact probe; spec and oracle move together
`UPDATE hydro.hydro_run h SET status = 'published' WHERE h.status = 'parsed' AND h.parsed_at IS NOT NULL`. The existing "never write parsed_at" scenario is narrowed by a MODIFIED delta from *references* to *writes* (no `SET parsed_at` in register or publish), and `tests/test_display_publish_status_only.py:78` (a source-text module, no DB) is rewritten to assert on the SET clause: `parsed_at` and `updated_at` never appear in the SET clause, and the WHERE carries `parsed_at IS NOT NULL` and no `river_timeseries` reference. The three behavioural regression rows run in the throwaway-DB lane: `tests/integration_helpers.py::seed_issue_126_data` stamps `parsed_at = now()` on `FORECAST_RUN_ID` only (`:313`, the run that gets fact rows at `:373-385`) and leaves `HINDCAST_RUN_ID` (`:329`, no fact rows) at NULL, so `tests/test_display_coverage_residual_debt_integration.py:191,220` keep asserting `== 1` and gain an assertion that `HINDCAST_RUN_ID` is still `parsed` (positive + negative row executed; the legacy-published row is asserted there too). The helper is shared with `tests/test_real_database_integration.py` and `tests/test_integration_helpers_bounded_teardown.py`, which are run in the same node-27 lane. `tests/test_node27_autopipeline_handoff.py` stays a call-site plumbing suite and is not claimed as the predicate oracle. `parsed_at` is stamped unconditionally before the status flip in the same transaction (parser :1192-1200), so every `parsed` row has it; the extra conjunct is belt-and-braces against a manual status edit and does not change the access path — measured on node-27 (2026-09-03, `EXPLAIN (ANALYZE, BUFFERS)`) the statement plans as a Bitmap Heap Scan on `hydro_run` via the partial index `hydro_run_display_product_basin_status_idx` (`Index Cond: status = 'parsed'`) with `Filter: parsed_at IS NOT NULL`, and NOT via `hydro_run_display_ready_basin_status_idx`, because the predicate does not constrain `basin_version_id` (the leading column of both partial indexes). Rejected: `AND rt.run_id = ANY(%s)` aid (adds a bound array + a second query for a probe that is now redundant, and extends #1342 debt); LATERAL probe (still depends on a compressed access path). The `NO_AIDS` oracle is re-pinned so that the publish statement's expected fact-table reference count is 0, and the `('hydro','river_timeseries')` census for `node27_autopipeline.py` decrements by one. A `parsed` run whose parser wrote zero river rows is published like any other parsed run — that is the #1789 owner decision and is stated in the docstring.

### D3 (#1476) — configured lock bound below the wall
`_DEFAULT_LOCK_TIMEOUT_MS = 5_000`; env `NODE27_RIVER_IDENTITY_BACKFILL_LOCK_TIMEOUT_MS` parsed with `_parse_int`; config assertion `lock_timeout_ms < duration_wall_ms` else refuse before any batch with the existing config-invalid wire path; `execute_batch` issues `SET LOCAL lock_timeout = <ms>` immediately after `SET LOCAL statement_timeout`; receipt `bounds.lock_timeout_ms` on both clean and stopped paths, schema `required`. Fake-cursor test: `55P03` on the batch → `stop.stage = lock_contention` (not `duration_wall`); `57014` path unchanged (halving retry then `duration_wall`). Runbook §4.6.2 caveat (`docs/runbooks/tier-node27-timeseries-storage.md:2204`) rewritten to the adopted state. Receipt schema: `bounds.lock_timeout_ms` is added as `required` under `additionalProperties: false` with `SCHEMA_VERSION` staying `"1.0"` — safe because no committed receipt artifacts exist and the only reader of on-disk receipts (`load_persisted_cursor`) checks `schema_version` alone and never JSON-schema-validates; the two backfill test files are updated with the new field. Rejected: derived value (`duration_wall // N`) — re-couples the two semantics operators need to tune separately.

## Invariant Matrix
