# node-27 external-contract snapshot probe: pre-mutation drift interception (#1089)

## Why

`packages/common/node27_container_contract.py` pins three MEASURED host
contracts (`CONTAINER_PG_RESTORE_REALPATH`, `SYSTEMD_UNSET_TIMESTAMP`,
`CLIENT_BACKEND_TYPE`). The hermetic lock
(`test_real_state_machine_bundle_verifies_task_4_5_pass`) anchors code
composability only — when node-27 upgrades systemd/PG/TimescaleDB/docker
or the `pg_wrapper` symlink target moves, the pinned constants and every
supervisor/verifier predicate bound to them drift silently, and the
drift surfaces only inside the next authorized mutation window as a
G-class misjudgment, burning an irreversible arm attempt (launch 7 →
G9, launch 11 → G14 precedent). #1089 closes this with a committed,
out-of-band, READ-ONLY drift probe: live observation vs a checked-in,
human-reviewed snapshot fixture.

Live recipe re-measurement (2026-08-02, node-27, all read-only):

- The recurring compression unit is inactive but HAS run this boot
  (`ExecMainStartTimestamp=Sun 2026-08-02 12:25:00 CST`), so the unset
  rendering is NOT observable on any real unit deterministically. The
  deterministic probe is `systemctl --user show <never-existing
  unit>.service -p ExecMainStartTimestamp` → systemd renders default
  properties for unloaded units → `n/a` (verified live on systemd 249).
- `CLIENT_BACKEND_TYPE` has a deterministic self-witness: the probe's
  own psql session, `SELECT backend_type FROM pg_stat_activity WHERE
  pid = pg_backend_pid()` → `client backend` (verified live). The full
  `backend_type` distribution is VOLATILE (parallel workers come and
  go) and must never be a compared field.
- `docker exec nhms-db readlink -f /usr/bin/pg_restore` →
  `/usr/share/postgresql-common/pg_wrapper` (verified live).
- Context versions measured: systemd 249 (249.11-0ubuntu3.21), Docker
  28.2.2, `nhms-db` = timescale/timescaledb-ha:pg15-latest (image id
  sha256:ad39c4fbc5c4...), pg_restore 15.2, server 15.2, timescaledb
  2.10.2. PG env comes from
  `infra/env/node27-timeseries-compression-replay.env` (sourced, never
  embedded).
- LIMITATION (recorded, fixture-review P1-2): the never-existing-unit
  witness measures systemd's *rendering* contract only; it does NOT
  witness the loaded-but-never-started-this-boot shape that
  `supervisor.py:1282-1293` / `live_evidence.py:834-845` assert as a
  whole-dict equality. A green `--check` therefore does not imply
  those checkpoints pass — and today they demonstrably would NOT (the
  recurring unit has run this boot via the daily 04:25 UTC timer);
  that pre-existing consumer defect is escalated as its own issue,
  out of this change's scope.

## What Changes

1. `scripts/node27_external_contract_snapshot.py` — standalone probe:
   - `--dump [--output PATH]`: measure and emit the snapshot JSON
     (stdout by default). No repo imports needed on the dump path, so a
     copied single file can run on node-27 without checking out a
     branch there.
   - `--check [--fixture PATH]` (default
     `packages/common/node27_external_contract_snapshot.json`): re-run
     the probes, diff live observations against the fixture's compared
     sections, AND assert the fixture's `contract` section equals the
     `node27_container_contract` constants (lazy import). Four-state
     exit contract, judged in this order: `0` ok; misalignment code
     (fixture.contract vs contract-module disagree — decided FIRST, no
     probe is spawned); drift code (live observation vs compared
     fixture value, report names every drifted field with expected and
     observed); probe-execution-failure code (a probe cannot run, or
     exits 0 with empty/key-missing output — never classified as
     drift; a drift report always carries a real observed value).
   - READ-ONLY by construction: the only argvs are `systemctl --user
     show`, `docker --version`, `docker inspect`, `docker exec nhms-db
     readlink -f ...`, `docker exec nhms-db /usr/bin/pg_restore
     --version`, and `psql --no-psqlrc -At -c "<SELECT/SHOW only>"`.
     Host binaries resolve through a pinned `/usr/bin` bin-dir seam
     (supervisor precedent) so hermetic tests repoint it at stub
     binaries; production default is asserted by a test.
2. `packages/common/node27_external_contract_snapshot.json` — the
   checked-in baseline, generated by one real node-27 `--dump`.
   Sections: `contract` (the three measured constants, 1:1, compared
   strictly), `host_context` (versions/image/entrypoint facts,
   compared), `informational` (volatile facts: backend_type
   distribution, measured_at, hostname, the REAL recurring unit's
   ActiveState/SubState/ExecMainStartTimestamp as counter-evidence for
   the limitation above — dump-recorded, NEVER compared). Every
   compared entry is `{"value": ..., "_provenance": {command, date,
   source}}`; comparison and alignment read `value` only, so a
   provenance-only edit can never red anything.
3. `tests/test_node27_external_contract_snapshot.py` — hermetic (test
   list canonical in tasks.md task 3): alignment guard both
   directions, mutation tests split by exit class, clean pass,
   read-only argv whitelist guard, bin-dir default pin,
   informational-never-compared, probe-failure classification trio,
   provenance-only edit, check-writes-nothing, dump shape.
4. Runbook: new "host-contract snapshot 漂移处置" section in
   `docs/runbooks/tier-node27-timeseries-storage.md` — how to trigger
   out-of-band (`ssh` + source env + confirm `XDG_RUNTIME_DIR` +
   `--check`), and the closed loop: drift → PR review → decide
   accept-new-contract (update fixture + `node27_container_contract.py`
   constants + hermetic-lock mutation-RED tests together) or roll back
   the host upgrade; NEVER a silent fixture update. PLUS: revise the
   existing §4.0 step-3 dry-probe (runbook :966-985 manual trio) to
   run `--check` first (exit 0 gates continuing), keeping the manual
   trio as script-unavailable fallback — until a timer/workflow is
   installed, that step IS the sole pre-mutation interception point.

## Non-goals

- Extending the hermetic lock's scope (code composability only, by
  design), or touching supervisor/verifier mutation-lane/gate
  semantics.
- Any auto-update path for the fixture (`--check` never writes;
  `--dump` writes only to stdout / an explicit local `--output`).
- Installing the weekly systemd timer / GitHub Actions workflow —
  operator-gated deployment; the runbook documents the invocation, the
  operator decides scheduling (recorded as a deviation-by-design from
  the issue's optional AC).
- node-22 (no live DB there); batch coverage of non-measured repo-side
  constants (`RECOVERY_TARGET_*` are repo decisions, not host facts —
  the alignment guard covers the fixture↔contract seam, host probes
  cover measured facts only).
