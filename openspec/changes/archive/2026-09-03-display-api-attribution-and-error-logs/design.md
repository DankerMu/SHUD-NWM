## Decisions

### D1 (#1728) — one name per surface, injected from the route layer
Each route module owns a `_APPLICATION_NAME` constant and passes it to its store: `Store.from_env(..., application_name=_APPLICATION_NAME)` / constructor kwarg, stored on the instance and forwarded as `fallback_application_name=` at every connect site the store owns. Seams, enumerated hop by hop: (1) `forecast_store._PsycopgTransaction.__init__(database_url, *, application_name=None)` (`:2635`, connect `:2653`), fed by `PsycopgForecastStore` (constructor + `from_env`) and by `PsycopgStationLookup` (`object_store_forcing.py:178`, `from_env` `:186`, builds the transaction directly at `:192`); (2) `model_registry._PsycopgTransaction.__init__` (`:3992`, connect `:4005`), fed by `PsycopgModelRegistryStore` (`:580`, `from_env` `:736`, `_transaction()` `:3409-3410`); (3) `PsycopgBestAvailableRepository` (`best_available.py:115`, `from_env` `:119`, connect `:275`), fed through `BestAvailableManager.from_env` (`:76-77`); (4) `PsycopgStateSnapshotRepository` (`state_manager.py:668`, `from_env` `:672`, connect `:1021`), fed through `StateManager.from_env` (`:255-263`). Every hop carries `application_name: str | None = None` and forwards it unchanged; the facade classes (`BestAvailableManager`, `StateManager`) only pass through. `data_sources.py` passes `nhms-api-data-sources` to both `PsycopgForecastStore.from_env` and `PsycopgStationLookup.from_env`; `forecast.py` → `nhms-api-forecast`; `best_available.py` → `nhms-api-best-available`; `models.py` → `nhms-api-models`; `state_snapshots.py` → `nhms-api-state-snapshots`. Default `None` keeps every existing caller and test byte-compatible; `packages/common` gains no hard-coded name and no new module. `pipeline.py:117` uses `create_engine(url, future=True, connect_args={"fallback_application_name": "nhms-api-pipeline"})` mirroring `hydro_display.py:142`. Operator `?application_name=` in the DSN still wins (libpq, #1714 D1). Rejected (b) one shared name: collapses read-only display and control-plane writes into one label.

### D2 (#1728) — deployed-unit closure guard with pinned adjudications

### D3 (#1726) — function-level delegated closure
In `tests/test_node27_connection_attribution_delegated.py`: for every module classified `ATTRIBUTED` (delegated), every function whose body contains a connect call must accept a keyword-only `connect` parameter (the injection seam), else the guard reports `module.function`. ### D4 (#1704) — log at the chokepoint, redact first, render into the message
`error_response()` emits `logger.log(level, "api_error request_id=%s code=%s status=%s path=%s details=%s", ...)` with `level = ERROR if status >= 500 else WARNING`, `details = _redact_error_details(details)` — a local wrapper in `apps/api/errors.py` that applies key-level redaction of the client-input keys first and then `redact_audit_payload` — `rejected_value` and `rejected_values` (recursing into the validation arm's `list[dict]`; the plural is the shape `packages/common/forecast_store.py` raises for unknown filter tokens and reaches the log through `ApiError.details` — added after round-1 review as an in-PR scope expansion), so raw client input under those keys never reaches the log even when it is not path-shaped. Residual (recorded under the Auth pack, and stated as such in the runbook — never as an absolute guarantee): free-text `details` values under any other key (`station_id`, `layer_id`, `run_id`, `cycle_time`, …) are redacted only when value-shaped (path/URI/checksum) or under a sensitive key, so client-supplied identifiers do reach the log verbatim; `parse_reason` stays verbatim by design. Bounds (added after round-1 review as in-PR scope expansions, both verified reachable): (i) the rendered `details` text is truncated to a fixed byte budget with a `…[truncated N bytes]` marker — the key pass runs before `redact_audit_payload` so a body-sized `rejected_value` subtree is never walked, and the validation arm over thousands of items cannot write a multi-MB line into the unrotated unit log (measured 8.5 MB from a 309 KB authorised POST); (ii) the inbound `X-Request-ID` is accepted only when it matches `[A-Za-z0-9._-]{1,64}`, else a UUID is minted — enforced at both `add_request_id` (`apps/api/errors.py`, the middleware every routed request passes) and `_ensure_request_id` (`apps/api/main.py`, the pre-body auth-deny path) — and `error_response()` re-runs the same check through `resolve_request_id`, which prefers the already-sanitised `request.state.request_id` and falls back to sanitising the header only when the state id is absent or non-conforming (unreachable over HTTP, since both earlier sites set a conforming state id first; kept as a shape-checked fallback instead of a bare `uuid4()`); rendering with `%r` was rejected because existing tests assert the bare `request_id=<id>` form. (iii) `path=` is the other client-influenced bare field: `request.url.path` is percent-decoded by the ASGI server, so a `%20`- or control-byte-bearing path segment could otherwise plant fake ` code=`/`request_id=` tokens or a NUL into the line (round-2 finding, reproduced on the real app); the line renders `urllib.parse.quote(path, safe="/")`, which leaves clean paths byte-identical and percent-encodes spaces, `=` and every control byte — `%r` was rejected here too (it would quote every line and still keep spaces). CRLF cannot reach the path at all (`urlsplit` strips `\r\n\t`), but that is CPython behaviour the tests now pin rather than rely on. Fields live in the message text, not `extra=`. `apps/api/main.py` installs, once, a `StreamHandler(sys.stderr)` with `%(asctime)s %(levelname)s %(name)s %(message)s` on `logging.getLogger("apps.api")` if that logger has no handlers; propagation stays **on** (pytest `caplog` attaches at root; under uvicorn's unconfigured root there is no second handler, and `lastResort` only fires when no handler is found along the chain, so no duplicate line). Must-preserve note: the pre-existing `apps/api/routes/models.py:33,308-322` logger is a child of `apps.api`, so its records now render through this handler (timestamped) instead of `lastResort`; its `extra=` fields remain unrendered as before. Rejected: writing to `uvicorn.error` (borrows another component's logger identity; breaks if `--log-config` ever changes). Slurm prefix stays out; recorded as a blind spot in the runbook.

## Invariant Matrix

- Governing invariant: every backend opened by the display unit carries a non-empty `application_name` naming its surface, and every error response produced by `error_response()` leaves exactly one redacted server-side line keyed by the response's `request_id`.
- Source-of-truth identity/contract: route-layer `_APPLICATION_NAME` constants; `fallback_application_name` kwarg on `_PsycopgTransaction` and the three stores; `X-Request-ID` / `request_id`; `_redact_error_details` over `redact_audit_payload`.
- Producers: route modules; store constructors/`from_env`; `PsycopgStationLookup.lookup`; `error_response()`.
- Validators/preflight: unit-level guard (`test_node27_connection_attribution.py`) and function-level guard (`test_node27_connection_attribution_delegated.py`).
- Storage/cache/query: `pg_stat_activity.application_name`; `/tmp/display-api.log`.
- Public routes/entrypoints: `_BUSINESS_ROUTERS` (seven) + runtime + conditional slurm; `apps/api/main.py` handlers.
- Frontend/downstream consumers: operators (`current-production-ops.md` cancel discipline); none in the frontend.
- Failure paths/rollback/stale state: logging must never raise into the response path (unexpected `details` types fall back to `repr`); handler install must not duplicate on re-import.
- Evidence/audit/readiness: post-merge `pg_stat_activity` receipt (zero empty names for `nhms_display_ro`) and a production-log grep of a synthetic `ApiError`'s `X-Request-ID` in `/tmp/display-api.log`; pre-merge scratch-port uvicorn smoke; guard red-proofs in the PR body.
- Regression rows:
  - `PsycopgForecastStore.from_env(application_name="nhms-api-forecast")` -> connect kwargs carry `fallback_application_name="nhms-api-forecast"`; `PsycopgStationLookup.from_env(application_name="nhms-api-data-sources").lookup(...)` -> same kwarg on its transaction; `from_env()` without it -> no such kwarg.
  - DSN with `?application_name=custom` + store name -> `custom` wins.
  - Router with a bare connect site -> unit guard red naming the site; `grid_registry_store.py` -> pinned `UNREACHABLE`, guard green; second connect function without `connect=` in an ATTRIBUTED module -> delegated guard red naming the function.
  - `error_response(..., details={"expected_path": "/ghdc/x.csv", "parse_reason": "concurrent-replace: ..."})` -> `caplog.text` contains `request_id=<id>`, `code=STATION_FORCING_FILE_MALFORMED`, `'expected_path': '[redacted]'`, `concurrent-replace:` verbatim; validation arm with `rejected_value: "sk-live-ABC"` -> `'rejected_value': '[redacted]'`.
  - Unchanged sibling: `hydro_display.py` name and MVT digest basis unchanged; `/api/v1/slurm` responses unchanged and unlogged (documented); `redact_audit_payload` byte-identical.
