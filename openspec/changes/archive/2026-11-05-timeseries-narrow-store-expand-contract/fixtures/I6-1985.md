### 3.4 Governance

`packages/common/node27_cold_governance_collection.py` adds catalog-only collection: `uncompressed_bytes`, `daily_ingest_bytes` (7-day mean by chunk `range_start` + size, no fact-row scan), `next_compressible_at` (`oldest uncompressed range_end + lag`, lag from the same `NODE27_TIMESERIES_COMPRESSION_LAG_SECONDS` the runner uses), `home_free_bytes`, `projection_status`. SQL may touch only `timescaledb_information.*` and `pg_*` size functions.

`scripts/node27_resource_governance.py`:

- `projected_peak_bytes = uncompressed_bytes + daily_ingest_bytes × max(0, days(next_compressible_at − watermark))`
- critical `PROJECTED_PEAK_EXCEEDS_HOME_FREE` when peak > `home_free_bytes − safety_margin_bytes` (default 100 GiB, CLI-overridable)
- warning `WORKING_SET_ABOVE_WARNING` when `uncompressed_bytes` > threshold (default 400 GiB, CLI-overridable)
- `WATERMARK_UNAVAILABLE` critical when the display watermark cannot be fetched (`projection_status = "watermark_unavailable"`)
- no uncompressed chunk: `next_compressible_at = null`, `projected_peak_bytes = uncompressed_bytes`, `projection_status = "no_uncompressed_chunk"`, no critical from this path
- `DATABASE_SIZE_ABOVE_WARNING` / `DATABASE_SIZE_ABOVE_CRITICAL` become **info**; they MUST NOT appear in `_critical_codes`, MUST NOT print `RESOURCE_GOVERNANCE_CRITICAL:…`, MUST NOT drive exit 1
- any remaining true critical still exits 1 after writing the receipt (`status=completed`); OnFailure body for the new peak-critical names `projected_peak_bytes`, `home_free_bytes`, `next_compressible_at`, working-set bytes — not database size as the lead
- CLI flags for `safety_margin_bytes` (default 100 GiB) and `working_set_warn_bytes` (default 400 GiB) must parse and reach the projection thresholds. The spec fits inputs (600 + 75×2 vs 900 → 750, default margin 100 GiB, exit 0) re-run with a raised margin that makes `home_free − margin < 750` MUST emit `PROJECTED_PEAK_EXCEEDS_HOME_FREE`, print the critical stderr line, and exit 1. A working-set flag below 600 GiB on the same inputs MUST emit `WORKING_SET_ABOVE_WARNING` without becoming critical by itself.

`schemas/node27_cold_governance_receipt.schema.json` and the unit-failure-alert body gain the working-set fields. Existing non-governance receipt schemas untouched.

Update `test_every_critical_recommendation_gets_its_own_line`: it currently plants `DATABASE_SIZE_ABOVE_CRITICAL` as a critical that must print and exit 1. After this change that code is info; the test must plant a still-critical code (root-free or the new peak code) instead of keeping a false critical.
