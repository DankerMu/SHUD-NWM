## Read-only diagnosis

The census client was connected over localhost to the live container and blocked
in libpq waiting for PostgreSQL, not on its FIFO or filesystem. The backend used
application name `nhms-ts-cold-census`; the separate display-watermark connection
completed normally.

The production backend ran the window-parity aggregate for
`hydro.river_timeseries`: one row containing total count, each business column's
non-null count, `bit_xor(hashtextextended(full-row-token, 0))`, and the numeric
sum of the same hash. At exactly the census's finite
`SET LOCAL statement_timeout = 3600000`, PostgreSQL cancelled the statement and
terminated its parallel worker. The session duration was 3600.258 seconds.

Read-only diagnosis found no lock wait, blocking PID, connection failure,
controller/FIFO wait, disk/inode exhaustion, process memory pressure or remaining
census backend. A concurrently observed ShareLock was compatible with the parity
SELECT and was not its timeout cause.

## Root cause and repair contract

`packages/common/compressed_chunk_cold_runtime_catalog.py::window_parity_sql`
generated the aggregate with the allowlisted parent hypertable as its `FROM`
target and relied on `[range_start, range_end)` predicates to reach the selected
chunk. The live result proves that this shape is not a bounded physical-origin
oracle at production size.

Child #2224 must:

1. select from the exact quoted durable origin schema/name for every production
   parity observation, with no parent fallback;
2. keep the parent-derived, physical-order business-column inventory and the
   half-open range as a second identity fence;
3. keep one database-side aggregate row and the existing count/non-null/checksum
   semantics;
4. prove on isolated PostgreSQL 15.2 / TimescaleDB 2.10.2 that compressed-origin
   reads transparently return target business rows and access no sibling chunk;
5. compare direct and `ONLY` origin forms and accept only the form that preserves
   transparent decompression;
6. retain the finite 3600-second production timeout as a safety ceiling; removing
   or raising it is not the fix; and
7. merge before #1895 restarts from G0 at a new exact reviewed SHA.

Direct compressed-storage-column hashing, `decompress_chunk` in the read-only
census, client row materialization, historical receipts and the failed private
run are forbidden substitutes.
