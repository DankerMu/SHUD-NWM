# Design — national discharge intersection closure

## Context

`_national_discharge_coverage_rows(session, *, source, cycle, since)` (`services/tiles/mvt.py`) runs two statements: the display-ready coverage rows (T1, filtered on `mi.active_flag` inside the statement) and then `SELECT DISTINCT mi.river_network_version_id FROM core.model_instance WHERE active_flag AND river_network_version_id IS NOT NULL` (T2). It returns `(rows, frozenset(active))`. Three judging sites consume it:

1. `national_discharge_cycles` — `if covered_networks != active_networks: continue` (per cycle).
2. `NationalCycleCoverage.complete` — `covered_networks == active_networks`; read by `national_discharge_valid_times`' per-cycle branch and by `apps/api/routes/hydro_display_postgis.py::_fetch_hydro_national_mvt_tile_bytes` (424 `MVT_NATIONAL_IDENTITY_INCOMPLETE` when `covered and not complete`).
3. `national_discharge_valid_times` no-argument branch — today NO set comparison (#2458).

Test fakes live in `tests/hydro_display_mvt_helpers.py` (`_NationalRouteSession`, `_NationalDiscoverySession`); order/race cases in `tests/test_hydro_display_mvt_scaling_coverage_order.py`; no-argument cases in `tests/test_hydro_display_mvt_scaling_discovery.py`, `tests/test_hydro_display_mvt_scaling_catalog.py`, `tests/test_hydro_display_mvt_scaling_catalog_cache.py` and the `_Session` cases of `tests/test_hydro_display_mvt_scaling.py` (a fake answering every statement with the same rows, so its sets are equal). (The issues cite `tests/test_hydro_display_mvt_scaling.py:<line>`; that file has since been split — locate by test / class name.)

## D1 — #2457 ruling: keep two statements, accept the numerator-shrink residual

The only way to close both race classes is one statement (one snapshot). Considered shapes:

- **LEFT JOIN merge** (the issue's sketch): zero-coverage networks become all-NULL rows, which leaks a new row shape into `_national_coverage_window`, `_national_run_rank` and `rows_by_cycle`, and rewrites the fourth run-selection site the module header requires to stay verbatim.
- **UNION ALL merge** (cheapest merge found): one statement returning the coverage subquery verbatim plus the active-network rows tagged by a discriminator column, split back into `(rows, active)` inside the helper. It keeps the caller shape, the four-site predicate text and the `h.status IN (...)` counts pinned by `tests/test_display_publish_status_only.py`. It still breaks the two fakes' statement dispatchers (`tests/hydro_display_mvt_helpers.py` `_NationalRouteSession.execute` and `_NationalDiscoverySession.execute`: the merged SQL contains `hydro.hydro_run`, so the discovery fake would route it to the coverage branch). Their constructor calls (46 + 15, which pass only rows and `active_networks`) could stay. What is lost outright: the two race subclasses `_ActivationBetweenStatementsSession` / `_CoverageRowVanishesBetweenStatementsSession`, which model the race AS two statements (4 + 1 constructor uses, and with them row 40d's whole kill list), the one `["digest","coverage","active","tile"]` sequence assertion (`tests/test_hydro_display_mvt_scaling_coverage_order.py`) with its adjacent per-statement param assertions, and the parametrized `executions` bind-sequence assertion. It also opens a node-27 EXPLAIN `Measured` lane for the new SQL.

Criteria (#2457 AC2 — at least one quantified or recorded as unquantifiable; all three are answered):

- **Frequency — recorded as unquantifiable.** The numerator side (`succeeded|parsed → failed`, `--force` zeroing) leaves no event: `workers/output_parser/parser.py` writes no `ops.pipeline_event`, `hydro.hydro_run` keeps only an overwritten `updated_at`, and no run-status history table exists. The denominator side is only partly visible (API activations write `ops.audit_log`; `scripts/node27_autopipeline.py`'s bare `UPDATE core.model_instance SET active_flag = true` does not). A frequency comparison cannot be built from the database; building an audit surface for it (a status-TRANSITION record for `succeeded|parsed → failed` and for `--force` zeroing) is out of scope. Note #2590's proposed `last_parse_failed_at` does not cover this class: it would be written only when `mark_run_failed` matches zero rows (a non-failable `published` run), while the shrink class is exactly the failable path.
- **Harm — same type, bounded.** Both classes list a cycle that some basin cannot render. Scope of the render-safety claim: the `/cycles` list, the per-cycle `/valid-times` branch and the canonical source/cycle tile route. On those, neither class renders WRONG data: a tile request for the listed cycle re-reads the pair on a cache miss, sees `covered ⊊ active`, and the canonical route answers 424 `MVT_NATIONAL_IDENTITY_INCOMPLETE` (site 2); a cached tile is the pre-failure render of data that was display-ready when cached. The stale listing self-heals within one catalog TTL (`DISPLAY_CATALOG_TTL_SECONDS = 60`) or, on the stale-while-revalidate path, `DISPLAY_CATALOG_STALE_MAX_SECONDS = 600` (`apps/api/display_cache.py`). The trigger window is millisecond-scale: T1's execution plus one round trip (matrix row 36 records a 3.7 ms index-scan node for the coverage statement; the whole two-set pre-check in tasks 1.1 ran in 277 ms on node-27).
- **Cost — quantified above** (M-L: two fake dispatchers rewritten, both race subclasses and row 40d's kill list lost and re-modelled, sequence/bind assertions rewritten, plus a node-27 EXPLAIN lane) against a p3, self-healing, render-safe residual. Frequency alone (recorded as unquantifiable) already satisfies #2457 AC2; harm and cost support it.

Ruling: keep the two statements in #2087's order. Reopen triggers: (a) a run-status transition record makes the shrink-class frequency measurable and it shows the class is routine; (b) a consumer appears that renders from the listing without its own coverage re-check (removing the render-safety argument above). Outside the claim, pre-existing and not counted as trigger (b): the no-argument `/valid-times` list paired with the legacy source-less national tile alias (`hydro_national_mvt_tile`, `source=None, cycle=None`), which by spec MUST NOT evaluate the coverage rule and so paints whatever networks hold runs with or without a race; no caller of that alias exists in the tree (frontend, catalog and prewarm all use source+cycle). Code: the helper docstring's shrink paragraph cites #2457 and this ruling; the characterization test `test_national_cycles_still_list_a_cycle_whose_covered_run_stopped_being_display_ready` stays, its docstring pointing at #2457's ruling. Matrix: row 40f records the ruling; row 40d's trade text points at #2457.

## D2 — #2458: the no-argument branch compares against the helper's active set

In `national_discharge_valid_times`, keep `active_networks` from `_national_discharge_coverage_rows(session, source=None, cycle=None, since=None)` and, after `latest_by_network` is built, `if frozenset(latest_by_network) != active_networks: return ValidTimeDiscovery(valid_times=[], limit=sample_limit, observed_count=0, truncated=False)` — the set rule of sites 1 and 2 (equality: catches subset, equal-size mismatch and superset alike). The existing `if not latest_by_network:` empty return MUST stay (before the set compare, or combined with it by `or`): rows = ∅ ∧ active = ∅ (fresh deployment, every network deactivated) passes `frozenset() != frozenset()` and would otherwise reach `max()` over an empty `coverage` list → `ValueError` → HTTP 500 on a public route. A test pins that state (rows `[]`, `active_networks=[]` → `[]`). Placement: before the per-row window validation, so the answer for a non-intersecting active set does not depend on row contents. The docstring bullet ("each active network's OVERALL latest run, intersected") gains the fail-closed clause; the helper docstring's "no-argument valid-times branch" mention stays true.

`since=None` stays (row 37: a network whose newest display-ready run predates the lookback stays IN the intersection). The NULL-cycle ranking (`_national_run_rank`) is untouched.

Behaviour without a race: identical whenever every active network holds a display-ready row (node-27 today: active 48 = covered 48, both differences empty, receipt in tasks 1.1). It flips from "a list" to `[]` only when an active network has no display-ready run — the correct fail-closed answer, stated in the PR body as a legacy-route behaviour change.

## Stated consequences (PR body)

- #2458 is a production no-op on 2026-09-23 data (48 = 48), a claim about today's data, not a stable property. When G1's #2504 window convergence is enabled on node-27 (`NODE27_TIMESERIES_RETENTION_WINDOW_DAYS` in the ingest env), expired out-of-window coverage rows whose facts are gone are lowered to zero; an active network whose ONLY display-ready runs are older than the window then drops out of `rows`, and the no-argument route answers `[]` where it previously silently dropped that network from the intersection. Intended fail-closed answer; the frontend and catalog never call this branch.
- #2457's residual stays open by ruling (D1), with explicit reopen triggers.
- Deviations from issue text: #2457 AC1 targets the ARCHIVED change's D2 (`openspec/changes/archive/2026-09-17-fix-national-discharge-coverage-snapshot-order/`); the ruling lives in this change's D1 instead, and the helper docstring cites #2457. #2459's "production diff comment-only" AC is per-issue: #2458's logic change is in the same PR.
