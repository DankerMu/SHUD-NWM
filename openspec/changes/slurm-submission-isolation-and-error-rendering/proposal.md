# Slurm submission isolation and gateway-error rendering

## Why

Three independent Slurm-surface defects, one PR at the user's request (batch E2). They share no code; they share only the gateway/compute surface.

- **#1908 (p1)** — `nhms-production validate-slurm --submit` pins its live worker inputs to a **stable** `run_id` path: `runs/<run_id>/input/manifest_index.json` plus `runs/<run_id>_success|_controlled_fail/input/manifest.json` (`services/production_closure/slurm_validation.py:718-725`, `:677-691`, `:704-712`). `--force` skips the exists guard (`:188-191`), and a failed `sbatch` unlinks that same formula-derived set (`:1020-1054`) with no check for a queued or running consumer. The array worker reads `NHMS_MANIFEST_INDEX` **after** sbatch returns (`infra/sbatch/run_shud_forecast_array.sbatch:79-82`), so a second concurrent `--force` run with the same `run_id` can overwrite the inputs submission A's tasks are about to read, or delete them outright when B's own sbatch fails. This is the one case the repo already solved elsewhere: `RealSlurmGateway.write_manifest_index` writes `cycle_id/manifests/<stage>_index_<timestamp>.json` by exclusive create (`services/slurm_gateway/real_backend.py:695-706`). It is also a violation of an existing requirement — `job-array-orchestration`'s "Manifest index is immutable after submission" already says a re-submission must produce a new versioned index.
- **#1909 (p2)** — `ARRAY_CAPABLE_JOB_TYPES` (`services/slurm_gateway/real_backend.py:133-137`) lists three of the four production array job types. `save_state_snapshot_array` has had an array template since the squash root and is in `PRODUCTION_ARRAY_TEMPLATE_NAMES` (`:139-145`), but the generic `POST /api/v1/slurm/jobs` — same bearer auth as the array endpoint (`services/slurm_gateway/routes.py:320-340`) — does not reject it (`:263`). A fully-authorized request renders the array template and submits it **without `--array=`**: Slurm accepts a singleton, `#SBATCH --output={{array_log_dir}}/%A_%a.*` is evaluated before the body's `mkdir -p`, and `SLURM_ARRAY_TASK_ID` defaults to `0`. The two sets have drifted once already (`b97c16e2` removed two retired types without adding this one).
- **#2308 (p3)** — `apps/api/routes/pipeline.py` renders `error_message` through the shared public renderer since #2305, but the Slurm gateway's own error `details` still passes only `redact_payload` (`:961-962`), which owns secrets and URL credentials, not host paths. So `details.command[0]` (the configured `slurm_bin_path`) and `details.stderr.snippet` (scancel/sacct stderr carrying absolute workspace paths) travel verbatim in the cancel 200 body (`slurm_failures[]`, `slurm_cancellation_gaps[]`, via `:930-944`) and in the queue-depth 502/504 body (`:864-878`). Two renderings of the same rule in one file.

## What Changes

- **#1908** — the live-submit lane's runtime inputs become **submission-unique**, not `run_id`-unique. One submission token per live submit (UTC timestamp, claimed by an exclusive create of the index with bounded retry, mirroring the gateway — the claim happens **before** any file that token names is written) gives the index `runs/<run_id>/input/manifest_index_<token>.json` and the two task run ids `<run_id>_<token>_success` / `<run_id>_<token>_controlled_fail`, so their manifests land under `runs/<that run id>/input/manifest.json`. That keeps `workers/shud_runtime/cli.py:60-69`'s safety gate satisfied — it binds the manifest path to `runs/<the entry's own run_id>/input/manifest.json` — so **no worker change is needed**. The script handed to `sbatch` is scoped by the same token (`runs/<run_id>/input/rendered_run_shud_forecast_array_<token>.sbatch`, derived from the claimed index) because it is the only carrier of the submission's identity — `NHMS_MANIFEST_INDEX` is baked into it and the array task reads that variable after `sbatch` returns; the stable `lane_dir` copy stays as evidence. Two concurrent submissions are then path-disjoint by construction: no lock, no `squeue` probe, nothing to mock. Cleanup after a failed `sbatch` unlinks only the paths this submission actually wrote, the submitted script included. The array log dir follows for free: it is derived from the index stem (`array_log_dir`, `real_backend.py:2217-2231`). The dry-run/fake-Slurm lane (`_uses_shared_workspace_inputs` false) keeps its stable lane-dir names byte for byte. `docs/validation/production-closure.md`'s `--force` wording (`:76-78`), its stable index path (`:80-90`) and its artefact list (`:101-103`) stop describing a switch that may overwrite live shared inputs and a fixed `manifest_index.json`.
- **#1909** — `ARRAY_CAPABLE_JOB_TYPES` stops being a second hand-maintained literal and is **derived** from the production array template names, so the four types cannot drift apart again; `submit_job` keeps refusing before sbatch with `details["endpoint"] == "/api/v1/slurm/job-arrays"`. The existing rejection test is parametrized over all four; a positive test proves `submit_job_array("save_state_snapshot_array")` still submits with `array_spec`.
- **#2308** — the two ops response surfaces render the gateway's `details` and `message` through the shared public evidence renderer, while the persisted `slurm_cancellation_gap` / `cancel_failed` events keep the raw (secrets-only) text. `_slurm_cancellation_gap_payload` therefore yields two shapes instead of one shared dict. The reason the event must stay raw is not anti-laundering (`[local-path]` is deliberately persisted evidence, per `pipeline-job-persistence`): it is that operators diagnose from the raw text and that the durable event is the record of what the scheduler reported. Retry's runtime-root recovery reads the same `("gateway_response", "manifest")` shape (`services/orchestrator/retry.py:1421`) but only on `submission` events (`:1382-1386`), so it is the oracle for the persisted shape, not a consumer of these two event types.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `job-array-orchestration`: the existing manifest-index immutability rule is extended to the production-closure live-submit lane and bound to cleanup.
- `real-slurm-gateway-contract`: the single-submit endpoint refuses every production array job type from one source of truth.
- `ops-monitoring-api`: gateway error evidence on the cancel and queue-depth responses renders host paths; the persisted events do not.
