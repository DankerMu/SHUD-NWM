## Context

This is one user-authorized operational batch, not three code features. Existing production implementations already consume the three configuration keys.
Change surface: node-27 display.env and node27-raw-retention.env; display restart; existing retention runner; read-only node-22 forcing evidence; runbooks/receipts.
Must preserve: display_readonly role and deny-write boundary, existing worker count and code version, cache/mirror identity, retention watermark, copyback ownership/0600 lock semantics, and node-22 active Python environment.
Governing invariant: each completion claim is bound to the actual service/configuration and observed lane; neither a sibling failure nor an overall successful tick may conceal the selected lane outcome.
Sibling surfaces: display process env/engine/pool/DB capacity, API tiles/catalog, display cache producer and PNG retention consumer, canonical lock lane, raw availability/forcing witnesses/scheduler candidates/published output.

## Goals / Non-Goals

Goals: safe pool mitigation, active PNG pruning configuration, evidence-backed upstream diagnosis, one reviewed PR.
Non-goals: cold-generation isolation, role-level SQL tuning, full-axis prewarming, #2360 ownership repair, scheduler retries, Slurm submissions, forcing rebuild, DB access from node-22, or dependency/environment migration.

## Decisions

Use existing configuration rather than changing defaults or adding tooling abstractions. Desired pool is 8+8 per worker, admitted only against live maximum/reserved/other-use capacity; keep workers unchanged.
Read the effective unit, process working directory, checkout status and running version before restart. Do not pull a production checkout just to apply configuration. Refuse ambiguous or changed-code restart until resolved.
Back up remote environment files in place with original permissions, modify only named keys, reject duplicate ambiguity, and never commit secrets or entire environment files.
Run retention plan-only before an existing production tick; inspect candidate roots and watermark before allowing deletion. Do not synthesize expired production data to force nonzero deletion.
Evaluate precip lane independently: configured root, safely evaluated configured source directories, no unavailable/unsafe PNG skips, explicit planned/deleted/failed counts. Reject root_missing/root_unsafe/source_unsafe as well as unconfigured. Zero naturally-expired candidates is legitimate only after actual lane evaluation, and is not deletion proof.
Canonical lock_unsafe is an expected separate #2360 failure; never chmod/chown/delete/bypass its lock to make this batch green.
Trace forcing provenance in the active file backend: FORCING_VERSION_ROW_ABSENT does not by itself prove a missing PostgreSQL row or explain producer failure.

## Risks / Trade-offs

Larger pool raises the exhaustion threshold, not isolation guarantees; retain #2346 as open.
Enabling pruning introduces deletion: approved existing retention rules only, plan first, no cache root mismatch or fallback.
Restart can deploy changed code accidentally: compare runtime/checkout and preserve code identity.
Historical timestamps cannot prove root cause: require executed diagnostic signal plus discriminating producer/configuration evidence.

## Migration Plan

Capture live capacity and service identity; back up both env files; apply pool keys; restart only display; verify health, root, layers, river/discharge tiles and read-only boundary. If smoke fails, restore only this operation's keys and restart original version, preserving unrelated concurrent edits.
Then back up/update retention key, run plan-only, inspect it, trigger one normal tick and retain per-lane summary. On incorrect-root/unsafe-plan evidence restore that key before execution; already deleted expired cache is regenerated by normal requests, not restored blindly.
Seams under test: real node-27 HTTP/DB/process config and retention summary; read-only node-22 producer/provenance logs.
Required evidence: tasks.md Evidence Floor and precise commands/results in receipt; no invented performance or recovery claim.
