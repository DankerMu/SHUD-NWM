### Pass 2 (#2405 + #2443) deviations

- **`final_evidence_artifact` cannot carry the terminal-file test in production.** Design D4 says the orphan rule keys on "whose `final_evidence_artifact` basename is absent in the root", but `scheduler_evidence.artifact_path_evidence` redacts that field to `[local-path]` under `scheduler_db_free_required` — which is how node-22 runs. Taken literally the test would never match, and since a pass's own `reserved_at` (mid-pass) is always newer than its own `started_at`, EVERY completed pass's lingering reservation would read as an orphan once its mtime aged past 2×ttl: a systematic false exit 3. `_orphan_reservations` therefore derives the terminal name from the RESERVATION FILENAME (`<pass_id>.pre_execution.json` → `<pass_id>.json`, the writer names both from the same `pass_id`) and additionally honours the payload spelling when it is a real filename. Semantically the spec rule ("its final evidence artifact is absent") is unchanged.
- **A reservation that cannot be placed in time is not reported.** No readable payload, no parsable `reserved_at`, or no evaluating-and-scope-complete pass to order against → skipped. The spec rule is conditioned on `reserved_at` being newer than that pass's `started_at`; an unplaceable reservation makes no such claim, and reporting it would have broken the legacy `test_pre_execution_evidence_is_not_scanned` fixture (a pass-shaped `.pre_execution.json` with no `reserved_at`) into a false exit 3. Residual: a reservation truncated mid-write is invisible to the rule. Bounded — `write_new_regular_file` writes the whole serialized payload to a fresh `O_EXCL` fd, and the reservation exists precisely to precede any mutation.
- **Timestamps are compared as `datetime`, not as strings.** `_format_utc` emits fractional seconds only when non-zero and `"...:00.5Z" < "...:00Z"` lexicographically — the wrong order exactly across the boundary this comparison decides. `_parse_utc` normalises the trailing `Z` and returns `None` (unplaceable, see above) on anything it cannot parse.
- **`lease_heartbeat_interval_seconds` is deliberately NOT in `scheduler_lease.__all__`.** That tuple is the compatibility re-export contract the `services.orchestrator.scheduler` facade asserts set-equality against; adding the name there and re-exporting it raised a `compatibility-facade-growth` entropy finding (`tests/test_entropy_audit_baseline_writer_summary.py` went red) whose remedy is an edit to `docs/governance/SCHEDULER_COMPATIBILITY_INVENTORY.md`, out of scope for this pass.
