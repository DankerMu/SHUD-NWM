# Design — `.resolve()` surface triage + loop convergence

Change surface: `scheduler_runtime_roots.py::_scheduler_root_check`; `journal_scope_census.py::_require_output_outside_root` + help text; four `strict=True` `.resolve()` sites with OSError-only handlers; a new AST guard for the `.resolve()` surface; ADR 0009 已知限制 2/3.

Must preserve:
- The `os.path.realpath` guard (`tests/test_path_canonicalization_family_guard.py`) stays green and its criterion unchanged; the census clause-2 exemption entry and its marker are byte-unchanged.
- `_scheduler_root_check` verdicts on non-loop inputs (ready/blocked, codes, key sets) are unchanged; the `unsafe_component_reason` pre-check arm is untouched; `tests/test_production_scheduler.py:~33834` (`published_check["allow_create"]`) stays green.
- `_db_free_path_check` (sibling lane, already converged) is not touched.
- Existing census codes `CENSUS_OUTPUT_UNWRITABLE` / `CENSUS_OUTPUT_INSIDE_JOURNAL_ROOT` / `CENSUS_OUTPUT_UNEXPANDABLE` keep their semantics; `UNWRITABLE` stays the after-receipt failure.
- The four dead-handler sites keep their current behaviour on non-loop input and on 3.13+.

Must add/change:
- D1 (#2453): both `.resolve(strict=False)` calls in `_scheduler_root_check` go through a strict-then-non-strict `os.path.realpath` helper — preferably the module's existing `_canonical_path` (already an ADR 0009 authority member with a clause-1 marker; update its reachability comment). The `except RuntimeError` arm is deleted. The `except OSError` arm around the first call becomes unreachable (`path` is required absolute earlier in the function, and the helper never raises for an absolute path); delete it or keep it with a one-line comment, and record which. The `workspace_root` anchor's handler tuple MUST keep `RuntimeError`, because `Path(workspace_root).expanduser()` can still raise it (no-home case). If the helper's semantics do not fit (e.g. `expanduser`), call `os.path.realpath` directly and either pass `strict=True` first or add a named exemption + `ADR 0009 clause 1` marker with the argument written in the body. Clause-1 argument to verify, not copy: `path.lstat()` runs before the containment verdict and its failure changes the verdict. The `allow_create` arm (path absent, creation allowed) is where clause 1 is weakest — the implementer must state in the body why it still holds (e.g. creation later dereferences via no-follow open) or which clause it relies on instead.
- D2 (#2454): `try: resolved = ...; root_real = ... except (OSError, ValueError) as error: raise OrchestratorError("CENSUS_OUTPUT_UNRESOLVABLE", OUTPUT_UNRESOLVABLE_MESSAGE, {"error_type": type(error).__name__, "output": str(output)}) from error`. Message constant, no path. Help lists the code next to the other three.
- D3 (#2452 dead handlers): each of the four handlers also catches `RuntimeError` and maps it onto the same outcome as its `OSError` arm (`continue` in the two export-line generators; the existing structured error in the other two). Tests construct a real symlink loop and assert the structured outcome on the running interpreter (on 3.11 this is red before the fix).
- D4 (#2452 guard): new AST guard over the four trees. Violator = a `.resolve()` attribute call whose `strict` argument is **not the literal `False` and not absent** (i.e. `strict=True`, or any non-literal value, treated conservatively; none exists today) that sits lexically inside the body of a `try` (same function) with a handler catching `OSError` / `IOError` / `EnvironmentError` (bare name or in a tuple), while no handler of that `try` or of an enclosing `try` in the same function catches `RuntimeError` / `Exception` / `BaseException` / bare `except`. Non-strict calls are deliberately excluded: for them the `OSError` arm is not what is dead — on 3.13+ the loop is folded and nothing is raised, so adding a `RuntimeError` arm would *create* the #2453 divergence (blocker on 3.11, folded pass-through on 3.13). Non-strict sites stay under the 3.1 triage. The fixture reviewer's read-only scan with this rule returns exactly the four named sites (`chain_runtime_utils.py::_python_runtime_export_lines`, `real_backend.py::_python_runtime_export_lines`, `file_orchestration_migration.py::_prepare_rollback_retention_root`, `slurm_validation.py::_bind_slurm_log_path`); if the implementer's scan differs, report it. Assert the violator set is empty (never a member list). Handlers catching only OSError *subclasses* (e.g. `FileNotFoundError`) are not violators: a loop escapes them on every interpreter alike. Module docstring states: why the realpath guard's `strict=True` criterion cannot be reused (strict `.resolve()` raises errno-less `RuntimeError` on ≤3.12); that enclosing-`try` coverage is accepted although an outer handler rarely has the inner `OSError` arm's outcome (stated limit); that the guard cannot judge #2453's "handler converges onto the same assembly" property (design review). Detector self-tests on synthetic sources: strict call in `except OSError` flagged; `(OSError, RuntimeError)` not flagged; subclass-only not flagged; enclosing-`try` coverage not flagged; **non-strict call inside `except OSError` not flagged**; no-`strict`-argument call not flagged.
- D5 (#2452 cross-version pin): a test that builds the shapes below in `tmp_path` and asserts, branching on `sys.version_info`, this table (the ≤3.12 band is exercised on 3.11, the ≥3.13 band on 3.14). The implementer measures every cell on both interpreters before writing the test; a cell that disagrees with this table is reported as a deviation, never silently adopted.

  | shape | form | ≤3.12 | ≥3.13 |
  |---|---|---|---|
  | loop `a -> b -> a` (resolve `a`) | `Path.resolve(strict=False)` | `RuntimeError`, `errno is None` | returns (no raise) |
  | loop `a -> b -> a` | `Path.resolve(strict=True)` | `RuntimeError`, `errno is None` | `OSError`, `errno == ELOOP` |
  | loop `a -> b -> a` | `os.path.realpath(strict=True)` | `OSError`, `ELOOP` | `OSError`, `ELOOP` |
  | loop `a -> b -> a` | `os.path.realpath()` | returns | returns |
  | `<missing>/../a` (a = loop) | `Path.resolve(strict=False)` | `RuntimeError`, `errno is None` | returns |
  | `<missing>/../a` | `Path.resolve(strict=True)` | `FileNotFoundError`, `ENOENT` | `FileNotFoundError`, `ENOENT` |
  | `<missing>/../a` | `os.path.realpath(strict=True)` | `OSError`, `ENOENT` (measure) | `OSError`, `ENOENT` (measure) |
  | `<missing>/../a` | `os.path.realpath()` | returns | returns |

  Receipts: `uv run --python 3.11 ...` and a **3.14** run (the #2452 acceptance names 3.14 explicitly), without rebuilding the project `.venv`.
- D6 (`_bind_slurm_log_path`): its `try` also holds non-strict `path.parent.resolve(strict=False)` / `path.resolve(strict=False)`. Adding `RuntimeError` to the handler tuple would turn a loop in the *log path* into `SLURM_ARRAY_TASK_LOG_UNSAFE` on 3.11 while 3.13 folds and continues. The loop test for D3 uses a loop in `log_dir` (hits the strict call; same result on both interpreters). For the non-strict pair the implementer records an explicit decision in design.md §Triage and the deviation report: either converge (e.g. the log path is subsequently opened/probed — if a kernel probe downstream gives the same verdict on both arms, show it with a loop-in-log-path test on both interpreters) or accept the 3.11-fails-closed / 3.13-folds divergence with the written reason. Same rule for any other non-strict call sharing a `try` with one of the four sites.

Governing invariant: at a site that claims to classify resolution failures (it has a handler for them), a symlink loop yields the same structured outcome (code, keys, exit contract) on every supported CPython, and never an untyped `RuntimeError`/`OSError` traceback. Unhandled non-strict sites that abort loudly on 3.11 and fold on 3.13 are triage objects (3.1), not violations of this invariant.

Sibling surfaces:
- Producers of the root check: `_scheduler_lock_evidence_root_preflight` (lock/evidence roots) and the runtime-roots preflight — both call `_scheduler_root_check`; both covered by the 36-cell matrix via the function, plus one end-to-end case through `ProductionSchedulerConfig`.
- Consumers of `checks`: `scheduler_evidence.py::write_prelock_blocked_evidence`, `scheduler_evidence_payload.py::_compact_root_preflight`, `scheduler_core.py` — read `status`/`writable`/`safe` only; must stay green.
- Census entrypoints: click `census_job_id_scope_command` and argparse `run_argparse_census_command` share `_census_command_result`; both parametrised.
- `.resolve()` sites with RuntimeError-only handlers (7 listed in #2452) — on 3.13+ those handlers are dead the other way; the triage records whether each converges (the #2453 lesson) and fixes any that diverge in payload shape, else records the reason.

Seams under test: `_scheduler_root_check` (function level, 36 cells) + one config-level end-to-end; the census CLI entrypoints via `_ENTRYPOINTS`; the four sites' public functions; the AST guard.

Required evidence:
- Root-check matrix (4 loop shapes × 3 fields `workspace_root`/`lock_root`/`evidence_root` × input strings raw + upstream-normalised; the upstream normaliser's output is byte-identical on both interpreters per #2453, so each run sees raw + one normalised string, and the receipt records that the two runs' normalised strings are byte-identical), on both `evidence_safe_paths` settings. Expected blocker reason per shape:
  - `evidence_safe_paths=False`: self-loop `a` → `SYMLINK`; `a/child` → `UNSAFE_PATH` (lstat ELOOP); raw `<missing>/../a` → `NOT_FOUND`; raw `a/../a` → `UNSAFE_PATH` (the kernel follows `a` as a middle component, `lstat` ELOOP; `SYMLINK` only after the upstream normaliser rewrote it to `<d>/a`); normalised strings → the reason the normalised shape yields on 3.14 today (measured, recorded in tasks.md).
  - `evidence_safe_paths=True`: raw strings containing `..` → `UNSAFE_PATH` from the component pre-check (7-key pre-check set, unchanged); other cells as above.
  - Expected key set per cell, derived in the test from a non-loop call on the same field through the full assembly (never a hard-coded list): for `SYMLINK` / `NOT_FOUND` cells, the key set of an ordinary (non-loop) symlink input; for `UNSAFE_PATH` cells where `lstat` returns an errno (`a/child`, raw `a/../a`, `allow_create` `a/child`), the key set of a non-loop `lstat`-errno input such as `<regular file>/child` (ENOTDIR → `UNSAFE_PATH`, carries `unsafe_reason`); for pre-check cells, the 7-key pre-check set. Codes are `SCHEDULER_ROOT_<FIELD>_<REASON>`.
- `allow_create` arm: loop inputs (self-loop and `a/child`) through `published_artifact_root` (`allow_create=True`, `must_exist=False`) on the runtime-roots preflight → `blocked` on both interpreters, same code/key set on both.
- Deleted-cwd relative `--output` and NUL `--output` → exit 1, empty stdout, stderr exactly one `CENSUS_OUTPUT_UNRESOLVABLE: <message>` line, no "Traceback"/"FileNotFoundError"/"ValueError"; journal-root byte snapshot unchanged.
- Loop input to each of the four sites → structured outcome, no escaping `RuntimeError` (red on 3.11 before fix).
- Guard green on the tree; synthetic violator makes it red.

Non-goals: rewriting the 141 unwrapped non-strict pairs wholesale; the realpath surface; `path_modes.py` ENOENT-vs-ELOOP vocabulary; EACCES divergence (#1554/#1623); a per-site shipped registry.

Review focus: (1) the clause argument written for the new canonicaliser call in `_scheduler_root_check`, esp. the `allow_create` arm; (2) the guard's detector is not bypassable by tuple/alias/nesting shapes it claims to cover; (3) triage table: every "无从句" row has a disposition; (4) new census code is BEFORE-census and distinct from UNWRITABLE; (5) no test weakened.

## Triage

**Method.** AST census, same as #2452: every `*.py` under `services/ workers/ packages/ apps/` (the realpath guard's `_iter_python_sources`), every `ast.Call` whose `func` is an `ast.Attribute` with `attr == "resolve"`, deduplicated by `(module, qualified function)`. Wrapped = lexically inside the body of a `try` in the same function whose handler catches `RuntimeError`/`Exception`/`BaseException`/bare.

**Counts on the day (branch base `17fa9f835`, before this change): 152 pairs / 223 call sites** — `services/` 110/164 · `workers/` 21/33 · `packages/` 18/22 · `apps/` 3/4; forms `strict=False` 111 · absent 105 · `strict=True` 7; non-strict wrapped 8 sites / 7 pairs, non-strict unwrapped 208 / 141. Identical to #2452's figures. After this change: 151 pairs / 221 sites (`_scheduler_root_check` no longer calls `.resolve()`).

**Vocabulary.** Clause = ADR 0009 clause the pair rests on (1 downstream dereference, 2 provable coincidence, 3 containment base / comparison operand with the judged side dereferenced); `n/a` = not a canonicalisation verdict; `无从句` = none of the three holds. 3.11 disposition = what a symlink loop does on the 3.11 pin: `caller-wrapped`; `loud abort acceptable (one-shot CLI | construction-time config | configured root, fail-closed)`; `pre-refused` (an lstat-based symlink/loop refusal upstream in the same flow stops the loop before this call on every interpreter, so neither the 3.11 abort nor the 3.13 fold is reachable except by a race); `changed`. `pre-refused` is an addition to the fixture's vocabulary (reported).
