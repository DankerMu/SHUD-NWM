## Why

node-27 的 `hydro.river_timeseries` 未压缩工作集已经大到威胁 `/home` 卷本身：2026-09-03 实测 779 GB（堆 363 + 索引 405），两个未压缩的 7 天 chunk 合计 747 GB，其中 text 主键索引一项 354 GB；`/home` 只剩 289 GB，按 38 流域 × 152 run/天的写入速率，下一次压缩峰值（chunk 91 压缩前 chunk 107 长满 + 下一 chunk 被 168 h 预报提前填充）约 1.25 TB，超过可用空间。根因不是数据量，而是三个乘数：每行 177 B 的 text 身份列（键/枚举形态只要 28 B，且 #1339 回填已把键列 null_frac 压到 0）、建在 text 五元组上的主键索引、以及 7 天 chunk + 168 h horizon + 2 天 lag 叠成的最坏 16–21 天未压缩窗口。已归档的 #1339–#1341 把键列、双写与键读路径铺好了，但 #1342（text 列退役）设计的 in-place cutover 在 TimescaleDB 2.10.2 上要求先 decompress 全部压缩 chunk（671 GB，盘装不下）并在窗口内对 13 亿行重建主键（ACCESS EXCLUSIVE、`CREATE INDEX CONCURRENTLY` 被 hypertable 拒绝），线上不可执行。本 change 用"新表 expand–contract"完成 #1342，并把 chunk 粒度、治理量法和 `met.forcing_station_timeseries` 的同型问题一并收口，使工作集与流域数线性关系的斜率降到现在的约 1/4，且告警能预测"下一峰值装不装得下"。

## What Changes

- **新窄表替换事实表（river）**：expand 迁移把现有 `hydro.river_timeseries` 改名为 `hydro.river_timeseries_legacy`，以正名新建仅含代理键/枚举列的 hypertable（`chunk_time_interval` 1 天；主键 `(run_key, river_segment_key, variable_e, valid_time)`；逐河段索引 `(river_segment_key, variable_e, valid_time DESC)`；发现索引 `(run_key, basin_version_key, river_network_version_key, variable_e, valid_time DESC)`；压缩 `segmentby (run_key, river_segment_key)`、`orderby (variable_e, valid_time)`，作为最后一条 schema DDL；不建 `valid_time` 单列索引；`lead_time_hours` 保持可空）。**BREAKING**：新表没有任何 text 身份列。消失的索引（`river_timeseries_valid_time_idx`、forcing 的 `qhh_latest_window_idx`）按 `timeseries-index-hygiene` 的证据门取 before/after EXPLAIN。
- **按 run 路由**：`hydro.hydro_run` 新增 `timeseries_store`（`legacy` | `narrow`，默认 `narrow`），expand 迁移按 parse 事实谓词（`parsed_at IS NOT NULL OR status IN ('parsed','published')`）回填 `legacy`，谓词之外残留在旧表里的行（此前中途失败的 parse）是可接受的过渡态：任何按 store 绑定的读分支都够不到，由 retention 清掉，迁移不做逐行探测；parser 在写窄表的事务内保持 `narrow`；所有读路径按 run 的 store 选 SQL 变体：模板先规范化（一 aid 一行、逐字标记在其上一行），legacy 变体 = 模板换表名，narrow 变体 = 删除"标记行 + 紧邻 aid 行"，渲染后断言可解析且不含 text 身份列；跨 store 查询由 union 组合子生成 `UNION ALL` 两分支。非模板面（publisher `_has_table`、copyback `required_columns`、QHH smoke 两脚本、计划形状钉子）按 store 分支；autopipeline 统计守卫的 hypertable 列表走车道的发现式集合。
- **写路径切换（BREAKING）**：parser 只写窄表，`ON CONFLICT` 目标改为键主键，replace 粒度与闭区间窗界不变；对 `timeseries_store = legacy` 的 run 的重解析 fail-closed 拒绝，走 `ops.ingest_recompute_decline` 账本（tick rc 0、永久不重开），parser CLI 独立退出码；不再有双写。
- **contract 收口（BREAKING）**：legacy 表被 retention 清空后由 contract 迁移 DROP（非空则 fail-closed 拒绝；先部署去掉路由列引用的代码）；删除 `hydro.cutover_river_identity_normalization()`、`hydro.verify_river_identity_normalization()`、`scripts/node27_river_identity_backfill.py` 及其测试；删除全部 `remove with #1342` 标记行与 aid 行及 legacy 变体；清零 oracle 收敛为"事实表 SQL 不得引用任何 text 身份列"；`tests/test_migrations.py` 的保留索引清单换成新表三索引；`timeseries_store` 列随 contract 删除；浏览器点击 P95 验收文字迁到 #1970 后关闭 #1342 与 #1336 epic。
- **回退**：expand 后、contract 前有可执行的反向序列（改名互换 + 回滚代码 + 路由列回置），允许"store 为 legacy 且窄表残留行"的中间态，在 throwaway 库演练。
- **生命周期车道适配**：压缩/retention runner、compression supervisor、capture、live-evidence 回放校验器、autopipeline 统计守卫、资源治理采集（七个消费点）的 hypertable 集合改为"正名 + 存在即纳入的 `_legacy`"（legacy 表消失后自动退出）；compression/retention receipt schema 接受 `_legacy` 键并新增 `legacy_chunks`；per-tick bound 推导按表分别建模（正名 1 天 chunk 每天 1 个；legacy 为零到达的有限存量），模板 `PER_TICK_BOUND=4` 重钉、`LAG_SECONDS` 赋值改为 172800；lag 维持 2 天、retention 维持 14 天。
- **治理量法改为工作集 + 峰值预测**：`node27_resource_governance` 新增"未压缩 chunk 总量"与"到下一可压缩时点的预计峰值"（按最近 7 天日均写入外推，单位天），critical 条件为 预计峰值 > `/home` 可用 − 安全余量；空态与 watermark 缺失有定义；整库 `pg_database_size` 阈值降为 info；receipt schema 与 OnFailure 正文同步。
- **forcing 后置批次**：`met.met_station`、`met.forcing_version` 增加 `INTEGER GENERATED ALWAYS AS IDENTITY UNIQUE` 键（先实测锁成本），枚举 `met.forcing_variable`/`met.forcing_unit`/`met.forcing_quality_flag` 复用 000050/000051 的三源并集方法；以正名新建窄 `met.forcing_station_timeseries`（主键 `(forcing_version_key, station_key, variable_e, valid_time)`，后继索引 `(forcing_version_key, variable_e, valid_time DESC)`，`segmentby (forcing_version_key, station_key)`，1 天 chunk；`source_id` 由 `forcing_version`、`basin_version_id` 由 `met_station` join 推导）；`met.forcing_version.timeseries_store` 路由；两处写方（含其写后校验查询）与九处读方经独立的 forcing 渲染器（两份注册模板，无标记机制，站点 census 钉住）切换；同样的 legacy 改名 → 14 天 → contract DROP。**串在 river contract 之后**执行。
- **文档与账本**：ADR 0002 追加修正案（Decision 4 的 segmentby 列表被新表设置取代、7 天 chunk 假设废止、FK 处置）；`docs/runbooks/tier-node27-timeseries-storage.md` 的表结构、容量、维护窗口、回退与 per-tick 推导章节重写；`openspec/glossary.md` 增补 `timeseries_store`/legacy/narrow 术语。

## Capabilities

### New Capabilities
- `timeseries-narrow-store`: 窄事实表的 schema、索引、压缩设置、chunk 粒度、路由列语义，parser 写路径与全部读路径的按 store 渲染契约（含 legacy 重解析拒绝与索引证据门）。
- `timeseries-store-expand-contract`: expand / contract 两段迁移的 DDL 顺序与 fail-closed 判据、legacy 表在车道与目录钉定工具中的过渡期归属、receipt schema、回退序列、维护窗口顺序，以及 node-27 实机 receipt 门。
- `timeseries-working-set-governance`: 资源治理的工作集与峰值预测指标、空态定义、critical 判据、整库体量降级为 info、receipt 与 OnFailure 正文契约。
- `forcing-narrow-store`: `met.forcing_station_timeseries` 的代理键、枚举、窄表、后继索引、路由、写读切换与 contract。

### Modified Capabilities
- `river-identity-normalization`: MODIFIED "in-boundary river_timeseries readers SHALL filter by surrogate keys with field-identical external responses"（text aid 只属 legacy 变体；narrow 变体无 text 谓词；`valid_time` 索引结论限定为 legacy）；REMOVED "river_timeseries identity columns SHALL have integer surrogate-key targets with an idempotent, bounded, receipted backfill"（authority 表的 000050 键保留为身份权威，backfill runner 与 cutover/verify 函数删除）、"writers SHALL dual-write"、"Out-of-boundary consumers ... transitional aids"、"The parser's replace chain SHALL locate rows by surrogate keys end to end"（其存活条款并入 `timeseries-narrow-store`）、"The forcing-copyback transitional pushdown aid SHALL be labelled"、"The identity backfill SHALL bound lock waits"。
- `output-parsing`: MODIFIED "TimescaleDB ingestion into river_timeseries"（列集与主键改为键形态）。
- `hypertable-compression`: MODIFIED "The compression per-tick bound MUST be a capacity-derived target consistent across template, live env, and receipts"（chunk 宽度为输入、legacy 兄弟按有限存量建模、模板 lag 赋值对齐 live）。
- 关系说明：`timeseries-working-set-governance` 只新增推荐码，`timeseries-db-retention` 的"critical 即非零退出"契约不变；`timeseries-index-hygiene` 的证据门以引用方式适用于本 change 消失的两个索引，其 requirement 文本不改。
