## DDL order (pinned)

Single-transaction expand migration, as required by the expand-contract spec, including rename, narrow schema, ownership and initial route classification. The migration runner's autocommit must not expose intermediate states. Reapplication must preserve routes of runs parsed narrow after the first application; initial legacy backfill runs only during initial expand.

Use one top-level DO block as the atomic unit under the existing statement-splitting autocommit runner. A compression-settings match skips only that ALTER, not ownership or route handling. A mid-migration failure rolls back the rename and all schema/route changes. Bootstrap nhms_ingest_rw in clean-cluster setup; missing required owner must fail, not silently change ownership expectations or grant PUBLIC privileges.

1. Rename `hydro.river_timeseries` → `hydro.river_timeseries_legacy` (skip if `_legacy` already exists and canonical is already the narrow table)
2. `CREATE TABLE hydro.river_timeseries` with PK `(run_key, river_segment_key, variable_e, valid_time)` and FKs `run_key → hydro.hydro_run(run_key)`, `river_segment_key → core.river_segment(river_segment_key)` inline. Columns exactly D4. No text identity columns. No FK on `basin_version_key` / `river_network_version_key`.
3. `create_hypertable('hydro.river_timeseries', 'valid_time', chunk_time_interval => interval '1 day', create_default_indexes => false)`
4. `river_ts_segment_time_key_idx (river_segment_key, variable_e, valid_time DESC)`
5. `river_ts_run_discovery_key_idx (run_key, basin_version_key, river_network_version_key, variable_e, valid_time DESC)`
6. `ALTER TABLE ... SET (timescaledb.compress, compress_segmentby = 'run_key, river_segment_key', compress_orderby = 'variable_e, valid_time')` — last schema DDL on the new table; guard like 000047 so re-run is a no-op
7. `ALTER TABLE ... OWNER TO nhms_ingest_rw`
8. `ALTER TABLE hydro.hydro_run ADD timeseries_store TEXT NOT NULL DEFAULT 'narrow' CHECK (timeseries_store IN ('legacy','narrow'))`
9. `UPDATE hydro.hydro_run SET timeseries_store = 'legacy' WHERE parsed_at IS NOT NULL OR status IN ('parsed','published')` — do not probe the legacy table for leftover rows

Header must record: no chunk is decompressed; `000047` is not re-run (it already matched the pre-rename name; expand owns the new-table settings). Do not change 000047, 000050 functions, or 000058 forcing interval.

## Parser (4.3)

`upsert_river_timeseries` writes only the D4 column set. INSERT `ON CONFLICT (run_key, river_segment_key, variable_e, valid_time) DO UPDATE` (value / lead_time / unit_e / quality_flag_e / basin_version_key / river_network_version_key as needed; no text identity columns). DELETE stays `run_key` + `river_network_version_key` + `variable_e` + closed `valid_time` window, both bound literals in one statement. Keys from `hydro_run` / `core.river_segment` as today.

Before any DELETE: read `timeseries_store`. `legacy` → raise `LegacyStoreWriteRefused` (typed, distinct from `CompressedChunkWriteError` / `CompressedChunkGuardError` / `OutputParsingError`). CLI maps it to a dedicated non-1 exit code and stderr token `OUTPUT_PARSE_LEGACY_STORE_REFUSED`. Autopipeline (4.4) treats that code as decline, not retry.

`mark_run_parsed` keeps `timeseries_store = 'narrow'` in the same transaction as the fact write. Do not flip a legacy run.

Parser `#1342` aids on the pre-delete existence probes: narrow path does not need text `run_id` pushdown (`run_key` leads segmentby). Drop those aids from the live write statements in this PR; census in `tests/test_river_ts_text_identity_cleanup.py` re-pins the parser register to the remaining narrow chain (zero text identity, statement count of the new chain, the one-marked-`run_id`-aid adjacency is gone).

## Decline ledger (4.4)

On parser exit `OUTPUT_PARSE_LEGACY_STORE_REFUSED`: write `ops.ingest_recompute_decline` with `reason_code = 'legacy_store_refused'`. Tick outcome `declined`, process rc 0.

Permanence: legacy_store_refused suppresses a run only while its authoritative timeseries_store remains legacy, regardless of regenerated product mtime or initial-state identity. Once that run is narrow, this legacy-store decline no longer suppresses it. Compressed-chunk declines retain existing exact-key reopen semantics. Both transitions require tests in this PR; no reopen behavior is deferred.

Receipt schema / tick summary: include `legacy_store_refused` counts the same way compressed-chunk declined rows are listed. DSN never in receipt.
