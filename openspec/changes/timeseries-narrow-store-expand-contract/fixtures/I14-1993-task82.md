## D1 — Migration `db/migrations/000066_forcing_timeseries_contract.sql`

The number is **000066** (000062–000065 are taken; older text saying 000062 is corrected in this PR).
Mirror 000060:

- One `DO $$` block (the migrate lane runs autocommit and splits statements; a multi-statement file is
  not atomic — `I9-1988-task62.md` D1).
- Window: `GREATEST(21, COALESCE(NULLIF(current_setting('nhms.retention_window_days', true), '')::integer, 0))`.
  21 is a floor; the GUC may only widen it.
- The time column is **one named constant** in the block (`cycle_time`), used to build the refusal count,
  so the choice is one token to revisit (`specs/forcing-narrow-store/spec.md`). No other spelling of the
  column name in executable text.
- Refusal 1: `met.forcing_version` has rows with `timeseries_store = 'legacy'` and that time column inside
  the window → `RAISE EXCEPTION` naming the count, the window and "nothing was changed".
- NULL is fail-closed: `met.forcing_version.cycle_time` is nullable (river's `end_time` is NOT NULL, so
  000060 had no such case). A legacy-routed row whose time column is NULL counts as in window.
- Refusal 2: the column is already gone but `met.forcing_station_timeseries_legacy` still exists → refuse
  (a half-applied state must not be papered over).
- Both gone → no-op replay.
- Drops, in this order: `DROP TABLE IF EXISTS met.forcing_station_timeseries_legacy` (PK, indexes, chunks,
  FKs, grants go with it), then `ALTER TABLE met.forcing_version DROP COLUMN IF EXISTS timeseries_store`
  (default and CHECK go with it). `met` has no cutover / verify functions; nothing else is dropped.
  Kept: `forcing_version_key`, `station_key`, the three enums, the narrow table and its indexes.
- No `SET lock_timeout` in the file (the migrate lane sets it; default 5 s). Header comment states the
  lock footprint: ACCESS EXCLUSIVE on `_legacy`, on `met.forcing_version` and `met.met_station` (FK
  removal) and again on `met.forcing_version` (column drop); the window procedure (D6); no down migration.
