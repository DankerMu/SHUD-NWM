## Ownership and implementation contract

Eight registered segment blocks are spanning by default: latest_issue_time, per_source_latest_cycles, latest_analysis_issue_time, analysis_segment_rows, forecast_segment_rows_selected_cycles, forecast_segment_rows, latest_run_type_valid_time, run_type_segment_rows. A selected (scenario,cycle) is not a unique run identity and MUST NOT be assigned one global store. Their authoritative hydro_run rows decide each fact's store in SQL. A9 is known-run after its existing header prefetch: one candidate, pinned run_id, same REPEATABLE READ transaction.

Use an explicitly authored, module-local segment fact-row source template with real callers in all eight blocks, not a general SQL rewriter/binder. Each store branch is produced by render_river_ts_sql(template, store); source has a key-only join to hydro_run for its matching timeseries_store and the existing basin/network/segment/enum identity predicates. Legacy branch retains every marked aid, narrow removes it. Explicit equal projections include only the common columns consumed outside (run_key, river_network_version_key, valid_time, value, unit_e); filters may use additional keys without projecting text identities. Caller-owned UNION ALL joins these row sources underneath one existing outer SELECT/join/group/distinct/order/limit layer. No whole-statement union, fact alias star, shared render_union_all, generic SQL parser or text replacement of arbitrary query shapes.

All eight methods keep one cursor execution per original fact statement. Source branch parameters are one shared named mapping, without legacy/narrow suffixes; outer selected-cycle/scenario/run/model/time params are also named so psycopg never mixes positional and named placeholders. Migrate the local identity/filter parameter helpers and all affected callers; do not leave parallel positional aliases or compatibility shims. Dynamic selected-cycle parameters use stable per-item names shared by the single outer VALUES CTE. Missing/unknown identity still yields existing empty results through authority key resolution. SQL-side per-run store binding is the real metadata lookup for spanning reads, not a constant helper or one extra query per fact row.

A9: add h.timeseries_store to the existing shared candidate_runs/header metadata seam; after nonempty header, validate its store is exactly legacy/narrow and render only that store's explicitly authored river_sample_rows template. Keep the pinned candidate run/store binding in the fact-row scan. Missing/null/unknown header store raises ForecastStoreError before the heavy scan, rather than defaulting legacy. Empty header still returns [] without heavy scan. No extra catalog query or added connection. Station CTEs, fast path, strict identity filters, candidate limit one, scalar header binds, coverage aggregation and result decision stay unchanged. Do not expose timeseries_store in response payloads.
