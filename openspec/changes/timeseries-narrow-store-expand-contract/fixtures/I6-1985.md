## Decisions the review asked for

1. **Live-evidence replay validator is the sixth hard-coded consumer and flips in this batch (option b).** `scripts/node27_timeseries_compression_live_evidence.py:61` `HYPERTABLE_KEYS` and `_validate_d3_catalog` (`:1879` exact set equality, `:1928`, `:2328`, `:2433`, the fixed nine-row `expected` compression_settings and `_require_exact_keys`) consume capture output; when capture emits the discovery set they must accept it: canonical two required and compression-enabled, `_legacy` siblings optional and text-shaped. Its plan-shape fixtures stay I5's (design D5). `EXPECTED_LAG_SECONDS = 604_800` (`:64`), `EXPECTED_BOUND` and capture's `interval '604800 seconds'` (`scripts/node27_timeseries_compression_capture.py:683/697`) are the frozen #1069 archival contract and are NOT re-pinned to 172800.
2. **Alert body.** There is no governance-specific OnFailure template: `scripts/node27_unit_failure_alert_once.sh` mails the last `NHMS_UNIT_FAILURE_JOURNAL_LINES` (30) journal lines for every lane. The requirement is therefore "every critical recommendation prints its own stderr line carrying the working-set fields, and info-level codes never print to stderr" — pinned next to `tests/test_node27_resource_governance.py:596` `test_every_critical_recommendation_gets_its_own_line` (info silence at `:619`). The systemd unit is not edited.
3. **Schemas.** `schemas/timeseries_compression_receipt.schema.json` has two constraint points: `per_table_totals` → `patternProperties` (canonical two keys required, `^[a-z_]+\.[a-z_]+_legacy$` optional) AND `allOf/0/then/properties/per_table_totals` (refused branch, `refused_table_total`) under top-level `additionalProperties: false`; both accept the `_legacy` key. `schemas/timeseries_retention_receipt.schema.json` adds `legacy_chunks`.
4. **`legacy_chunks` shape is a mapping** `{ "<schema.table>_legacy": <integer ≥ 0> }` keyed by legacy table name, present only when at least one `_legacy` sibling exists in the catalog (design D7 "按表"). The I9/I14 entry gate reads the table's entry: `legacy_chunks["hydro.river_timeseries_legacy"] == 0` (forcing: `legacy_chunks["met.forcing_station_timeseries_legacy"] == 0`). `specs/timeseries-store-expand-contract/spec.md`, `design.md` and `tasks.md` 6.1 / 8.2 are corrected in this PR to that reading.
5. **Catalog-only guard is a new seam** (the spec's "existing catalog-only guard test" was wrong — `tests/test_node27_resource_governance.py:96` is two-device arithmetic; spec corrected in this PR). The new test asserts the collection SQL references only `timescaledb_information.*`, `pg_*` catalog/stat relations and `pg_database_size`-style functions, never `hydro.`/`met.` fact tables.
6. **Key-shaped expectations are encoded for both tables now** so I12 needs no supervisor/capture change (tasks 7.3): river canonical = `segmentby (run_key, river_segment_key)`, `orderby (variable_e, valid_time)` (design D4); forcing canonical = `segmentby (forcing_version_key, station_key)`, `orderby (variable_e, valid_time)` (design D9). Text-shaped expectations are today's. Three-state rule per table: sibling present → canonical key-shaped + sibling text-shaped; sibling absent → canonical text-shaped (today). If I10's measurements change D9, I12 re-pins the forcing row.
7. **Lag source for governance.** Governance sources only `infra/env/node27-resource-governance.env` (`scripts/node27_resource_governance_once.sh:7`); the compression template carries a write-role DSN and says not to sync. Decision: governance reads `NODE27_TIMESERIES_COMPRESSION_LAG_SECONDS` from its own env / `--compression-lag-seconds` flag with default 172800; `infra/env/node27-resource-governance.example` gains that line plus the margin/warning-threshold variables; a cross-template pin test asserts the governance default equals the compression template's `LAG_SECONDS` so they cannot drift. Missing/unparseable value → CLI config error, non-zero exit (existing behaviour for bad config). The receipt echoes `compression_lag_seconds`; the template cross-pin covers template↔template only, so a drift of the deployed node-27 compression env versus the governance env is NOT caught by any unit test — it is caught by the I8 rollout receipt (and the orchestrator's pre-merge read-only receipt) comparing the echoed value with the deployed compression env; recorded as the accepted residual. `design.md` D8 and `specs/timeseries-working-set-governance/spec.md` are aligned to this wording in this PR.
8. **Governance is a discovery-set consumer.** `scripts/node27_resource_governance.py:277` hard-codes `{"river_timeseries","forcing_station_timeseries"}`; the collection module derives the set through the shared helper and the recommendation keys on it, so `uncompressed_bytes` covers canonical ∪ `_legacy`. Helper consumers: compression runner, retention runner, supervisor, capture, live-evidence validator, autopipeline stats guard, governance collection (seven call sites, one helper).
9. **"Identical to today" is scoped**: SQL text of runner/retention/autopipeline necessarily changes (IN-list → discovery) and the supervisor SQL pins (`scripts/node27_timeseries_compression_supervisor.py:1317-1325` family) are re-pinned; what must not change without a sibling is the hypertable set, per-table expectation, receipt key set/shape and exit code. Comparator: the committed compression and retention receipts under `docs/runbooks/receipts/tier-node27-timeseries-storage/` are the pre-change fixtures — a test drives the receipt writers on a no-sibling fake catalog and asserts the top-level and `per_table_totals` key sets equal those receipts' (and `legacy_chunks` absent); the supervisor's no-sibling expectations are the existing unit-test expectations, which pass with zero edits apart from the SQL-text pins.
10. **Frozen constants untouched**: live-evidence `EXPECTED_LAG_SECONDS`, capture's `604800` intervals, the benchmark's 168 h window, `packages/common/timescale_write_guard.py:69-70` (write path, I7).

## Must-preserve

- Without a `_legacy` sibling (today's node-27 catalog) every tool's hypertable set, per-table expectation, receipt key set/shape and exit code equal today's (decision 9); the supervisor's `validate_current_d3` and capture's `HYPERTABLE_KEYS` keep the text-shaped expectation for a canonical table without a sibling; no string "legacy" in tick output.
- Every committed historical compression / retention receipt and both governance schema examples validate against the updated schemas; refused-mode compression receipts with a `_legacy` key stay constrained by `refused_table_total`.
- `timeseries-db-retention`'s contract "critical ⇒ non-zero exit" is unchanged; every critical recommendation prints its own stderr line; info-level codes print nothing to stderr.
- Lag stays 2 days (template `LAG_SECONDS=172800`, governance default 172800, pinned equal) and retention 14 days; `PER_TICK_BOUND=4` kept with the re-derived comment; benchmark window and the frozen #1069 constants untouched.
- Governance projection is catalog-only (guard test); the watermark comes from the compression runner's existing fetcher with the same fail-closed semantics.
