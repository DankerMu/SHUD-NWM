## Decisions the review asked for

1. **Live-evidence replay validator is the sixth hard-coded consumer and flips in this batch (option b).** `scripts/node27_timeseries_compression_live_evidence.py:61` `HYPERTABLE_KEYS` and `_validate_d3_catalog` (`:1879` exact set equality, `:1928`, `:2328`, `:2433`, the fixed nine-row `expected` compression_settings and `_require_exact_keys`) consume capture output; when capture emits the discovery set they must accept it: canonical two required and compression-enabled, `_legacy` siblings optional and text-shaped. 2. **Alert body.** There is no governance-specific OnFailure template: `scripts/node27_unit_failure_alert_once.sh` mails the last `NHMS_UNIT_FAILURE_JOURNAL_LINES` (30) journal lines for every lane. The requirement is therefore "every critical recommendation prints its own stderr line carrying the working-set fields, and info-level codes never print to stderr" — pinned next to `tests/test_node27_resource_governance.py:596` `test_every_critical_recommendation_gets_its_own_line` (info silence at `:619`). 3. **Schemas.** `schemas/timeseries_compression_receipt.schema.json` has two constraint points: `per_table_totals` → `patternProperties` (canonical two keys required, `^[a-z_]+\.[a-z_]+_legacy$` optional) AND `allOf/0/then/properties/per_table_totals` (refused branch, `refused_table_total`) under top-level `additionalProperties: false`; both accept the `_legacy` key. `schemas/timeseries_retention_receipt.schema.json` adds `legacy_chunks`.
4. **`legacy_chunks` shape is a mapping** `{ "<schema.table>_legacy": <integer ≥ 0> }` keyed by legacy table name, present only when at least one `_legacy` sibling exists in the catalog (design D7 "按表"). The new test asserts the collection SQL references only `timescaledb_information.*`, `pg_*` catalog/stat relations and `pg_database_size`-style functions, never `hydro.`/`met.` fact tables.
6. **Key-shaped expectations are encoded for both tables now** so I12 needs no supervisor/capture change (tasks 7.3): river canonical = `segmentby (run_key, river_segment_key)`, `orderby (variable_e, valid_time)` (design D4); forcing canonical = `segmentby (forcing_version_key, station_key)`, `orderby (variable_e, valid_time)` (design D9). Round-1 review reproduced that a rule keyed on sibling presence alone reverts the canonical table to text-shaped once the contract drops the sibling (supervisor red after I9); therefore each contract PR (6.2 river, 8.2 forcing) flips its table's default to key-shaped and deploys before the DROP — one constant per contract, no discovery-logic change. Round-1 review decisions (PR #1997, base 989c3cf7):

11. **`daily_ingest_bytes` divides by the days the in-window uncompressed chunks actually cover** — `max(1/24, days(watermark − earliest in-window range_start))`, never a fixed seven (round 2: the floor is hours, not a day — under today's 7-day chunks only the open chunk is in-window and a whole-day floor divides its first-day bytes by 1 → rate under-reported by 1/age, a green flip on the drained-backlog state; `test_a_single_fresh_chunk_never_divides_by_a_fraction` is re-pinned to the hours floor with a 6 h / 10 GB → 40 GB/day case). The node-27 receipt at 989c3cf7 showed `daily_ingest_bytes == uncompressed_bytes // 7` byte-for-byte, i.e. a rate that under-reports whenever the uncompressed window is shorter than seven days (steady state: lag+1 days). Over-reporting is the fail-safe direction for a capacity guard. The `test_daily_ingest_is_the_seven_day_mean_anchored_on_the_watermark` contract is re-pinned to the covered-days reading plus a steady-state case (compressed chunks inside the window do not shrink the rate).
12. **`WORKING_SET_UNAVAILABLE` is a critical of the same class as `WATERMARK_UNAVAILABLE`.** Timescale block `blocked` (collection exception) or an empty catalog for a canonical table sets `projection_status = "working_set_unavailable"` and exits 1; `test_missing_working_set_block_changes_nothing` is replaced by the critical pin. An empty catalog must never be read as `no_uncompressed_chunk`. The unavailable shape reports `uncompressed_bytes` / `uncompressed_chunks` / `projected_peak_bytes` as `null` (schema widened to integer-or-null for those three; a zero would read as "it fits"), the collection block records the raw error text in `postgres.working_set_error` (same precedent as `timescale_status.error`; NOT redacted — the resource-governance summary is written by `_write_summary` without `redact_payload`, and the field cannot carry a DSN because `fetch_display_watermark` collapses every failure to its type name and only catalog `cursor.execute` errors reach it; round-2 correction, with a `working_set_error` assertion riding on the existing `_RaisingCursor` test), and the probe isolation in retention lives inside `_legacy_chunks()` so the dry-run path is covered too.
