## Decisions the review asked for

1. **What a "registered template" is.** The renderer takes SQL text; it has no registry. The registry is test-side: one new module `tests/river_ts_template_registry.py` (keyed `<module>:<name>`, one block per reader module in stable file order so the four wave-2 PRs append without colliding) whose entries carry `source` (a callable returning the template text — runtime-assembled forecast_store blocks come through the existing capture-cursor harness at `tests/test_river_ts_text_identity_cleanup.py:437,472`), `kind` (`statement` | `fragment`), `params` (`positional` | `named`) and `expected_aids`. `mvt.py:1493-1530`'s conditional valid_times SQL registers as two entries. Fragments (`_SEGMENT_IDENTITY_PREDICATE_SQL`, `forecast_store.py:92-113`) have no table name: table rename is a no-op on them and the structural check applies to the fragment alone.
2. **Text identity column authority.** The whole constant group moves as one from `tests/test_sql_shape_helpers.py:121-162` into `packages/common/river_ts_render.py`: `SANCTIONED_TEXT_PUSHDOWN_COLUMNS` (:121), `FORBIDDEN_TEXT_FACT_COLUMNS` (:126), `LATERAL_PROBE_TEXT_PUSHDOWN_COLUMNS` (:143), `TEXT_IDENTITY_COLUMNS` (:145, derived = sanctioned + forbidden — the derivation moves with it) and `TEXT_AID_COUNTERPARTS`; the tests re-import them so `test_sanctioned_and_forbidden_column_sets_are_disjoint_and_complete` (:877), `test_every_text_identity_column_has_a_declared_counterpart` (:871) and `test_the_sanctioned_ceiling_is_the_shared_one_not_a_private_copy` keep their meaning against the shared module (no private copy anywhere).
3. **"Parses" means the structural check**, because the repo has no SQL parser and three placeholder dialects coexist (`%s`, `%(name)s`, `:name`): balanced parentheses; no `WHERE AND` / `FROM AND` / `ON AND` / `WHERE\n)`; no `AND`/`OR` left dangling before `)`, before end of text, **before a clause keyword** (`LIMIT`, `ORDER`, `GROUP`, `HAVING`, `UNION`, `EXCEPT`, `INTERSECT`, `WINDOW`, `OFFSET`, `FETCH`, `RETURNING` — and, round-2 ruling, the same join/from family the region-stop regex already enumerates: `JOIN`, `INNER`, `CROSS`, `NATURAL`, `WHERE`, `ON`, `FROM`, `SELECT`, `WITH`, `VALUES`, `SET`, and the outer-join arm spelled `(LEFT|RIGHT|FULL)(\s+OUTER)?\s+JOIN` — bare `LEFT`/`RIGHT` would false-positive on `LEFT(col, n)` function syntax; one keyword family, shared by both checks; plus a new `ON <keyword>` fault so an ON chain whose only conjunct was an aid is refused — verifier H6 measured the widened family refuses 0 of 20 registry entries and catches the four `AND JOIN` / `ON JOIN` / `AND LEFT JOIN` / `AND WHERE` shapes) **or before another connective** (`AND AND`, `OR OR`, `AND OR`); no `WHERE` immediately followed by a clause keyword; no marker string; no `SELECT … FROM x AND …` (round-1 review C4 widened the enumeration).
4. **Positional parameters.** Removing a `%s` aid changes the caller's tuple arity. `render_river_ts_sql` returns a `RenderedSql` with `sql` and `removed_placeholders` (ordered indices of positional placeholders that were removed; empty for named templates). `test_forecast_store_segment_blocks_bind_every_placeholder_they_grew` (`tests/test_river_ts_text_identity_cleanup.py:599`) stays green because no caller is wired.
5. **Renderer module and the statement census.** `packages/common/river_ts_render.py` holds the two table-name constants and no statement; it is **registered** in `REGISTERED_SOURCES` + `RIVER_TABLE_CENSUS` with its measured mention count (expected **2**: `_river_table_mentions` counts substrings and the `_legacy` literal contains the canonical name) and wired in `scripts/select_ci_tests.py`, so a statement sneaking into the shared helper is red. Registry closure: for every registered production file, the sum of canonical-name mentions over that file's registry entries' source text equals `RIVER_TABLE_CENSUS[file]` minus the file's declared `NON_TEMPLATE_MENTIONS[file]` (comment/prose/identifier mentions that are not read statements — a declared-offset dict a reader must know exists: bumping it is the only way to hide an unregistered read site, so it is reviewed line by line) (fragments contribute 0; both mvt valid_times branches count), so an unregistered zero-marker read site is red too.
6. **Equivalence oracle (golden; predicate chains only — see must-preserve).** Before any template edit, capture every registry entry's base-SHA text (`git show 51f9d273:<file>` for constants; capture cursor for assembled blocks) and commit the normalised form — `outer_predicates`-folded, split on top-level `AND` per chain, sorted — as `tests/fixtures/river_ts_templates_51f9d273.json`. A test asserts `render(entry, legacy)` with the table name restored has the same conjunct multiset per chain as the golden. **Chain** = one AND-chain delimited by its own opening keyword or bracket: each `WHERE` chain, each `JOIN … ON` chain, the body of each subquery / `EXISTS` / `IN (SELECT …)` / `CROSS JOIN LATERAL (…)` (its inner `WHERE` is its own chain, never merged with the outer one — `outer_predicates` keeps lateral bodies, `tests/test_sql_shape_helpers.py:374-384,566-584`), and the inside of each `OR (…)` disjunct; a fragment is one chain. Chains are compared positionally (same count, same order of chains, same multiset within each), so a conjunct migrating from a lateral body to the outer WHERE is red. Conjunct order inside one chain is explicitly NOT preserved (see must-preserve); everything else is.
7. **Oracle ownership per file** (the two registers are mutually exclusive by design, `tests/test_river_ts_text_identity_cleanup.py:114-124` and `:1461`): cleanup oracle owns forecast_store, publisher, forcing_copyback_backfill, parser (and the non-reader files already in `REGISTERED_SOURCES`); `tests/test_river_ts_read_path_surrogate_keys.py` owns mvt, hydro_display, display_coverage. Each file's marker/aid census pin lives in its owning oracle.

## Must-preserve

- For every registry entry, the `legacy` variant with `hydro.river_timeseries_legacy` substituted back to `hydro.river_timeseries` has the same conjunct multiset per predicate chain as the base-SHA text (golden: WHERE / ON / subquery / lateral / OR-disjunct chains compared positionally), the same parameter names/placeholders inside those chains and the same disjunction truth table — i.e. equal **modulo whitespace, marker placement and conjunct order within one chain**. The golden is blind outside predicate chains (SELECT list, FROM/JOIN targets, LIMIT/ORDER BY): those are covered by the reviewer's per-block diff (evidence mapping 1.1) and the sibling substring pins, and this PR's production diff touches nothing outside WHERE/ON chains and comments (round-1 review C11).
- No reader is wired to the renderer; no executed production SQL changes meaning. The rewritten disjunctions (`forecast_store.py:1903` shape, `display_coverage.py:410/417`) keep the same truth table: `OR (` + marker + `rt.run_id = %(scan_run_id)s AND` + `rt.run_key = (...))`.

- After the PR the only marker form in production code is (apart from the two non-aid tag lines inside `packages/common/river_ts_render.py` declared in `NON_AID_MARKER_TAG_LINES`) the verbatim `-- transitional compressed-chunk pushdown aid, remove with #1342`, one per aid, on the line immediately above the aid; a marker never sits on a `WHERE`/`ON`/keyword line.
