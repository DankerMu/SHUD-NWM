## Contract decisions

- Observe `config.pgdata_root` directly with existing `safe_resolve`/`disk_usage`/device primitives.
  Capacity is available bytes (`f_bavail`), never total, free-including-reserved, a path-prefix guess,
  or an arbitrary matching home/cold label. Add one config-driven filesystem observation, following
  existing `repo_root_fs` and `object_store_fs` patterns. Reuse existing PGDATA usage observation;
  do not add a second recursive du or scan shared `/data/GHDC` itself.
- Current `working_set` carries `working_set_free_bytes` and `working_set_filesystem` with resolved
  `path`, `device_identity`, observation `status` (`ok`, `unavailable`, `ambiguous`) and a
  `blockers` list of bounded stable codes (empty when valid). Path/device may be null only when
  unavailable; capacity bytes are null when binding is unavailable/ambiguous. Its current writer
  no longer emits `home_free_bytes`. Independent `filesystem.filesystems.home` telemetry remains.
- Direct target observation avoids a selection among root/home/repo/object-store aliases. Several
  labels legitimately sharing one device are not ambiguity. Missing target identity or conflicting
  observations of the configured target (for example target stat and existing PGDATA usage identity
  disagreeing) is unavailable/ambiguous, never a choice of whichever label has most free space.
- Keep peak calculation/catalog/watermark status distinct from target capacity validity. Invalid
  target evidence makes `WORKING_SET_FILESYSTEM_UNAVAILABLE` critical with an explicit reason and
  exit 1, even for an empty working set. It must not silently become healthy by skipping comparison.
  Valid target plus no uncompressed chunks retains the existing zero-peak/no-peak-critical behavior.
- Capacity sampling itself does not require another recursive size scan. If the already-required
  PGDATA du observation is unavailable, retain its honest unavailable evidence and emit an independent
  `PGDATA_USAGE_UNAVAILABLE` critical rather than treating that audit as healthy. This satisfies the
  issue's du-failure acceptance without relabeling statvfs bytes or adding scans. A du identity conflict
  invalidates target binding; ordinary same-device aliases do not.
- Valid target plus projected peak greater than `working_set_free_bytes - safety_margin_bytes`
  emits `PROJECTED_PEAK_EXCEEDS_WORKING_SET_FREE`; equality fits. Existing peak formula, lag, watermark,
  catalog-only SQL, warning threshold, database-size info severity and generic critical exit remain.
- Stderr/OnFailure uses the new critical identifier and prints projected peak, available bytes,
  resolved target path/device, working-set bytes and next-compressible time. Never echo DSN/password
  or raw secret-bearing exception text. Existing redaction, tee/PIPESTATUS and alert ownership remain.
- Preserve cold receipt schema version 1.0 and its existing history reader. Its optional `working_set`
  uses two closed, unambiguous shapes: historical home-based shape accepted for historical reading,
  new destination-bound shape required from current producers. No compatibility alias in the writer
  or runtime comparator. No-working-set historical receipts remain valid. Historical shape is not
  valid current destination-capacity evidence and must not trigger a hidden home fallback.
  Preserve the main audit envelope identifier unless a real consumer contract requires a recorded
  change; change the shared working-set payload and all current consumers together.
